# ⑤ 사람 화면 — A 독립 구현

## 범위와 접속

2026-11-12. 본인 인물 목록·검색·페이지 조회·상세와, 저장된 personId로 연결된 확정 미팅 이력 읽기를 구현했다.
사용자의 명시적 승인으로 공용 `App.jsx`에 `/people` 로그인 보호 경로를, `DashboardLayout.jsx`에 사람 메뉴를 추가했다. contracts와 B/C/D 도메인 파일은 변경하지 않았다.

기존 앱에서 로그인한 같은 브라우저·같은 origin에서 Vite 개발 서버의 아래 주소를 연다.

```text
http://localhost:5173/people
```

5173이 아닌 포트로 실행했다면 실제 Vite 주소를 사용한다. 기존 JWT 클라이언트가 같은 origin의 로그인 정보를 사용한다.
로그인되지 않았거나 API가 실패하면 오류로 표시하며 샘플로 대체하지 않는다.
실행에 백엔드·MySQL이 필요하다. 이미 저장된 인물·이력 조회에는 Ollama가 필요 없다.
기존 앱의 사람 메뉴에서도 열 수 있다. 이전 `src/components/identity/people.html` 주소는 `/people`로 이동하며 로그인 보호도 공용 앱을 따른다.

## 화면 동작

- 검색은 기존 GET /api/persons의 이름·별칭·현재/이전 소속·연락처 부분 문자열 검색이며 20명 단위다.
- 상세에는 ID·대표 이름·등록 별칭·현재/이전 소속·부서·직함·이메일·전화·채널을 표시한다. 누락 값은 미등록이다.
- 현재 페이지에서 이름이 중복되면 동명이인 표시를 한다. 전체 대장에 동명이인이 없다고 단정하지 않는다.
- 고객/계약 인력 구분 필드가 Person 계약에 없어 해당 필터를 추측해 만들지 않았다.
- 타임라인/회의록은 미팅 시각 최신순, 미기록 시각은 마지막이다. 20개씩 추가 조회한다.
- 약속 기록은 현재 불러온 확정 회의록의 원문 근거를 보존한다. 이행 상태가 없어 열린/완료 약속으로 판정하지 않는다.
- FULL 다인 미팅 약속은 공동 기록으로 표시하고 특정 개인의 약속으로 단정하지 않는다. LIGHT는 해당 personId의 followUp만 표시한다.
- 할 일 탭은 C 보드 링크와 연결 대기 안내다. C의 counterpart 연결·보관 정책 확인 전 임의 목록/상태를 만들지 않았다.
- 인물 등록·수정·삭제·병합은 이 화면에 추가하지 않았다. 인물 목록/상세는 읽기 전용이다.

## 이력 API

```text
GET /api/persons/{personId}/meetings?page=0&size=20
```

기존 ApiResponse의 data에 **기존 meeting_note 계약 배열**을 반환한다. 새 계약 필드를 만들지 않았다.

- 먼저 기존 PersonService로 인물 ID·본인 소유권을 검사한다.
- B의 기존 조회 저장소/서비스를 읽기만 한다. 사용자·원본 소유자, 미보관, 원본 미삭제, CONFIRMED를 검사한다.
- participants.personId 또는 LIGHT perPerson.personId가 정확히 일치할 때만 반환한다.
- 이름/회사/후보/A의 미반영 HUMAN 선택을 조합해 B 연결을 추정하지 않는다.
- 따라서 B가 선택을 회의록에 반영하기 전에는 A에서 선택 저장이 성공했어도 이력에 나오지 않을 수 있다.
- 미팅 시각과 ID로 정렬하고 필터 후 페이지를 적용한다. 본인 회의록을 먼저 읽고 메모리에서 선별하는 초기 구현으로, 대량 데이터에서는 DB 쿼리 최적화가 필요하다.
- 형식이 깨진 저장본은 기록 없음으로 숨기지 않고 오류로 처리한다.

## 확인과 남은 연결

백엔드 단위 테스트에 정확 ID·동명이인·LIGHT·정렬/페이지·타 사용자·초안/보관/삭제 제외·형식 검사·컨트롤러 인증 검사를 추가했다.
프론트는 상세/미기록 표시·원문 근거·개인 귀속 미확인·빈 이력 안내·요청/실패 처리를 검사한다.
브라우저 자동화 호스트가 없어 실제 브라우저 시각/클릭 검증은 수행하지 못했다. SSR 렌더 검사와 ESLint, 전체 빌드는 별도로 확인했다.

남은 팀 검토: B의 참석자 반영과 기존 연결의 정확성, C 인물별 할 일·보관 정책.
실제 DB/브라우저의 이력 흐름 검증은 B 연결 뒤 별도로 필요하다. 이번 작업에서 DB에 테스트 데이터를 넣거나 다른 담당 테이블을 수정하지 않았다.

## 2026-11-12 시안 반영

사람 화면 전용 `people.css`로 공용 제목 크기·중앙 정렬 영향을 분리했다. 초기 독립 탐색 사이드바는 제거하고 공용 DashboardLayout의 실제 메뉴·헤더를 사용하도록 통합했다. 시안의 2열 목록/상세, 선택 카드, 아바타, 접힌 상세, 탭과 미팅/메일 기록 카드를 적용했다. 좁은 화면에서는 세로 배치한다.

오른쪽 위 **가상 화면 예시** 버튼은 `peoplePreview.js`의 명백한 가짜 자료를 메모리에서만 읽는다. 화면에 미리보기 표시를 유지하며 DB·API·localStorage에 저장하지 않는다. 실제 목록이 비거나 실패해도 자동으로 예시를 대신 보여주지 않는다. 미리보기의 가짜 회의록은 실제 문서로 링크하지 않는다. 다시 누르면 실제 대장으로 돌아간다.

고객/계약 인력 필터와 다음 미팅 준비 버튼은 사용할 데이터·연결이 없어 비활성이다. 약속 기록 수·회의록 수는 현재 불러온 자료 기준이며 열린 약속/할 일 수를 추측하지 않는다. 전체 할 일은 기존 보드 링크로 확인한다. 실제 타임라인은 저장된 회의록의 원문 근거를 펼쳐 확인할 수 있다.

브라우저 접근 호스트가 없어 실제 브라우저 시각·클릭 검증은 하지 못했다. SSR·기능 검사, ESLint, 공용 레이아웃 렌더 검사·전체 프론트 빌드로 검증했다.

현재 구성: `PeopleScreen.jsx`가 실대장/명시적 미리보기 전환을 관리하고, `PeoplePage.jsx`가 목록·상세를 렌더한다. 사람 화면 전용 스타일만 재정의해 다른 화면의 제목·레이아웃에는 영향을 주지 않는다. 공용 변경 범위는 App의 import/보호 경로, DashboardLayout의 사람 메뉴 및 선택 메뉴의 aria-current 표시다. 고객 타임라인 등 기존 경로는 유지한다.

검증 참고: 공용 DashboardLayout의 기존 99행 알림 effect에 `react-hooks/set-state-in-effect` lint 오류 1건이 있으며 변경 전 HEAD에서도 같은 오류를 확인했다. 사람 화면 및 App 변경 lint는 통과했다. 해당 알림 로직은 이번 메뉴 연결 범위에서 수정하지 않았다.

## 2026-11-13 확인

401 로그인 문제는 사용자가 해결했다고 확인했다. 로그인 설정은 수정하지 않았다. A 백엔드의 MODEL 응답 거절을 수정하고 실제 JWT 필터·격리 MySQL 선택 저장 검증을 추가했다. 실제 브라우저에서 B 반영 뒤 사람별 이력을 확인하는 항목은 남아 있다.
