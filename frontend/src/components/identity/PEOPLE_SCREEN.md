> 2026-11-22 작업 기준. 이번 후보 검색·DB 기반 식별 ID·병합/되돌리기 변경을 포함한다. 화면·API 구현 여부와 main 반영 여부는 구분하며, 반영 상태는 해당 PR에서 확인한다.

## 접속과 구성

공용 앱에 로그인한 뒤 **사람** 메뉴 또는 `http://localhost:5173/people`을 연다. 포트가 다르면 실제 Vite 주소를 사용한다. 공용 DashboardLayout의 메뉴·계정 헤더와 로그인 보호를 사용한다. 예전 개발용 `people.html`·`people-entry.jsx`는 제거했다.

`PeopleScreen.jsx`는 실제 대장/명시적 가상 예시 전환, `PeoplePage.jsx`는 목록·상세·이력, `PersonMergePanel.jsx`는 병합·감사·되돌리기를 담당한다. 전용 `people.css`로 2열 목록/상세와 좁은 화면의 세로 배치를 구성한다. 사람 메뉴는 ContactRound 아이콘으로 고객 타임라인과 구분한다.

실제 조회·저장에는 백엔드·MySQL이 필요하다. 저장된 대장·회의록을 조회하거나 수동 병합하는 데 Ollama는 필요 없다. 인증·API 오류는 표시하며 샘플로 자동 대체하지 않는다.

## 선택한 인물이 이력에 보이는 시점

B의 참석자 반영은 이미 구현돼 있다. 현재 흐름은 다음과 같다.

1. 확인 화면에서 인물을 선택하면 A가 HUMAN 결과와 수정 기록을 저장한다.
2. **선택 저장만으로 B 초안 참석자 ID가 즉시 바뀌지는 않는다.**
3. B가 회의록을 확정할 때 저장된 CONFIRMED 결과를 resolutionId로 읽어 participants 및 LIGHT perPerson에 personId를 반영한다.
4. A 사람 화면은 이 연결이 저장된 CONFIRMED 회의록을 조회한다. 아직 DRAFT인 메모·선택되지 않은 참석자·연결 ID가 없는 회의록을 이름만으로 가져오지 않는다.

초안의 처음 참석자 연결과 LIGHT 표시 이름 대응에는 이름 기반 제한이 남아 있다. 동명이인·이메일만 있는 참석자를 모두 해결했다고 보지 않는다. 상세 저장 경계는 [인물 선택 설명](../../../../backend/src/main/java/com/salesmap/backend/person/IDENTITY_SELECTION.md)을 참고한다.

## 병합·되돌리기

사람을 선택한 뒤 **중복 인물 병합·기록**을 연다. 다른 인물을 검색하고 이름·소속·연락처를 비교한 뒤 같은 사람임을 체크해야 병합 버튼이 활성화된다. 대표 이름·현재 소속은 유지하고 등록 별칭·연락처·명시된 이전 소속과 인물 이력을 함께 조회한다. 다른 현재 회사를 이전 회사라고 추측하지 않는다.

병합된 원본은 목록·식별 대장에서 제외되지만 원본 document는 보존한다. 기존 회의록의 personId도 수정하지 않는다. 감사 정보에서 양쪽 병합 전 상태, 병합 사용자·시각, 되돌린 사용자·시각을 확인한다. 되돌리면 해당 연결만 해제되고 다른 병합 연결은 유지된다. 그룹 전체의 중첩 병합은 기존 병합을 먼저 해제해야 한다.

D-026에 따라 수동 병합은 AI 학습용 revision이 아닌 감사 기록이다. 자세한 API·트랜잭션·제한은 [병합 설명](../../../../backend/src/main/java/com/salesmap/backend/person/PERSON_MERGE.md)을 참고한다.

## 읽기·관리 API

- GET `/api/persons?q=...&page=0&size=20`
- GET `/api/persons/{personId}`
- GET `/api/persons/{personId}/meetings?page=0&size=20`
- GET/POST `/api/persons/{personId}/merges`
- POST `/api/persons/{personId}/merges/{mergeId}/undo`

미팅 API는 기존 ApiResponse data에 기존 meeting_note 계약 배열을 반환한다. 인물의 본인 소유권을 먼저 확인하고, 본인 회의록·원본 소유자, 미보관·원본 미삭제·CONFIRMED를 검사한다. participants 또는 perPerson의 정확한 ID를 사용하며, 수동 병합한 경우에만 현재 병합 ID 집합까지 포함한다. 약속 탭도 같은 ID 집합을 사용한다.

FULL 다인 미팅 약속은 공동 기록으로 표시하고 개인에게 귀속시키지 않는다. LIGHT는 해당 인물/병합 ID 집합의 followUp만 표시한다. 회의록의 원래 ID·근거 문장은 보존한다.

참석자/perPerson JSON이 깨진 회의록은 그 회의록만 제외한다. noteId만 로그에 남기고 원문·인물 단서·예외 본문은 기록하지 않는다. 제외 후 정렬·페이지를 적용하며 DB/조회 서비스 장애는 숨기지 않는다. 현재 본인 회의록을 읽어 메모리에서 선별하므로 대량 데이터에서는 DB 조회 최적화가 필요하다.
