# 준비 서비스 명세서 (S-04 ~ S-10)

> 이번 학기에는 **명세만** 쓰고 구현하지 않는 7종이다 (`overview.md`, D-013, D-016). 할 일 종류의 정의와 경계는 [`task-types.md`](task-types.md)가 기준이다.
> 체크리스트와 알림 시점은 **회사 검토 전 초안**이다. 회사의 준비 체크리스트를 받으면 이 문서를 고친다 (`decisions.md`의 "회사 회신 대기").

## 한눈에

| 서비스 | 할 일 종류 | 기준일 | 알림 시점 | 지금 데이터로 가능한가 | 먼저 필요한 것 |
| --- | --- | --- | --- | --- | --- |
| S-04 계약 만료 대응 면담 | `RENEWAL_INTERVIEW` | 계약 종료일 | D-60 / D-30 / D-7 | ❌ | 계약·투입 인력 데이터 |
| S-05 제안서·인력 리스트 제출 | `PROPOSAL_SUBMISSION` | 제출 마감일 | D-5 | ✅ | 없음 |
| S-06 미채택 후보 통보 | `REJECTION_NOTICE` | 선정 결과 확인일 | 당일 | ⚠️ 일부 | 발송 대기함, 후보 목록 |
| S-07 서류 취합·회수 독촉 | `DOC_COLLECTION` | 서류 발송일 | D+7 / D+14 | ✅ 안내까지 | 독촉 문구는 발송 대기함 |
| S-08 종료 평가 작성 | `END_EVALUATION` | 투입 종료일 | D-0 | ❌ | 계약·투입 인력 데이터, 평가 양식 |
| S-09 수익성 검토 | `PROFITABILITY_REVIEW` | 조건 협의일 | 협의 전 | ❌ (학생 범위 밖) | 단가·원가 자료, 회사 기준 |
| S-10 신규 인력 소싱 착수 | `SOURCING_START` | 인력 요청일 | 1영업일 안 | ⚠️ 일부 | 회사 휴무일, 후보 풀 |

구현한다면 **S-05 → S-07 → S-10 → S-06 → S-04·S-08 → S-09** 순서를 권한다. 앞의 셋은 지금 있는 할 일·메일·기한으로 시작할 수 있고, 뒤로 갈수록 새 데이터나 회사 기준이 필요하다.

## 모든 서비스의 공통 규칙

| 항목 | 규칙 | 근거 |
| --- | --- | --- |
| 시작 조건 | 사람이 **확정(`CONFIRMED`)** 한 할 일의 `taskType`으로만 시작한다. `NONE`이나 초안에서는 시작하지 않는다 | D-023, D-030 |
| 날짜 계산 | 알림 시점·기한은 규칙 코드로 계산한다. LLM은 날짜를 정하지 않는다 | 규칙 4 |
| 기준일을 모를 때 | 지어내지 않고 "기준일 확인 필요"로 표시하며 알림을 잡지 않는다 | 규칙 3 |
| 알림 | **아침 묶음에만** 넣는다. 즉시 알림으로 보내지 않는다 (하루 3건 제한은 일정 30분 전 알림용) | 규칙 6 |
| 외부 메시지 | 초안은 **발송 대기함까지만** 만든다. 보내기는 사람이 누른다 | 규칙 2 |
| LLM 사용 | 안내·초안 문장 작성에만 쓴다. 쓴 문장에는 원문 근거를 붙이고, 근거가 없으면 "기록 없음 · 확인 필요"로 둔다 | 규칙 3 |
| 사람 결정 기록 | 항목을 열거나 무시하면 `screen=BRIEFING`, `targetType=BRIEFING_ITEM`, `action=OPENED`/`IGNORED`로 남긴다 | ML-4, `revision.schema.json` |
| 데이터 범위 | 담당자 본인의 데이터만 본다 | D-025 ⑤ |
| 상태 변경 | 서비스가 할 일 상태를 직접 바꾸지 않는다. 필요하면 "완료로 옮길까요?" 제안만 한다 | D-025 ① |

**지금 코드의 동작:** 할 일 종류 분류와 아침 묶음은 7종 모두 동작한다. 다만 준비 항목은 전용 내용 없이 "할 일의 근거와 필요한 자료 확인" 한 줄이 나온다 (`BriefingService.preparationItems`).

## S-04 계약 만료 대응 면담

- **목적:** 계약 종료 전에 재계약 의사를 확인할 면담을 놓치지 않게 한다.
- **시작 조건:** `RENEWAL_INTERVIEW`. 재계약·갱신 의사 면담만 해당하고, 재계약서 작성은 `CONTRACT_PREP`이다.
- **알림:** 계약 종료일 기준 D-60, D-30, D-7. 면담이 끝났거나 할 일이 완료·취소되면 남은 알림을 멈춘다.
- **필요한 데이터:** 계약 종료일, 고객 담당자, 투입 인력, 지난 회의록. **계약 종료일과 투입 인력은 지금 데이터 형식에 없다.**
- **준비 체크리스트 (초안)**
  - 계약 종료일과 갱신 조건 확인
  - 지난 미팅의 불만·요청 사항 정리
  - 투입 인력의 연장 의사 확인
  - 면담에서 물어볼 질문 정리
- **산출물:** 면담 준비 안내 (지난 기록 요약에 출처 표시).
- **사람이 정하는 것:** 면담 여부와 시기, 재계약 조건.
- **회사 확인:** 알림 시점이 업무에 맞는지, 계약 정보를 어디서 가져올지.

## S-05 제안서·인력 리스트 제출

- **목적:** 제출 마감을 놓치지 않고 필요한 자료를 미리 모으게 한다.
- **시작 조건:** `PROPOSAL_SUBMISSION`. 제출 준비·작성·송부가 해당하고, 이미 냈는지 확인만 하는 일은 `NONE`이다.
- **알림:** 할 일 기한(`dueDate`)을 마감으로 보고 D-5. 기한이 없으면 "마감일 확인 필요"로 표시한다.
- **필요한 데이터:** 할 일 내용·기한·원문 근거, 고객 요청 사항, 지난 회의록. **모두 지금 있다.**
- **준비 체크리스트 (초안)**
  - 공고·요청의 제출 조건과 마감 확인
  - 고객 요청 사항과 제안 내용 대조
  - 제출할 인력 리스트와 이력서 확인
  - 제출 방법과 받는 사람 확인
- **산출물:** 제출 준비 안내. 제출 메일 초안을 만든다면 발송 대기함까지.
- **사람이 정하는 것:** 제출할 후보, 제안 내용, 제출 실행.
- **회사 확인:** 제안서·인력 리스트 양식, D-5가 충분한지.

## S-06 미채택 후보 통보

- **목적:** 선정 결과가 나온 뒤 탈락 후보에게 알리는 일을 빠뜨리지 않게 한다.
- **시작 조건:** `REJECTION_NOTICE`. 미채택 결과·사유를 알리는 일만 해당하고, 단순 재연락은 `NONE`이다.
- **알림:** 선정 결과를 확인한 당일 아침 묶음. 기준일을 모르면 할 일 기한을 쓰고, 그것도 없으면 "확인 필요"로 표시한다.
- **필요한 데이터:** 후보 이름·연락처, 선정 결과. **후보 목록과 발송 대기함은 아직 없다.**
- **준비 체크리스트 (초안)**
  - 선정 결과가 확정됐는지 확인
  - 통보 대상 후보 확인
  - 알려도 되는 사유의 범위 확인
- **산출물:** 통보 문구 초안 (발송 대기함까지).
- **사람이 정하는 것:** 통보 대상, 문구, 발송. **개인에게 민감한 내용이라 후보별로 사람이 확인한 뒤에만 보낸다.**
- **회사 확인:** 통보 문구, 사유를 어디까지 알릴지.

## S-07 서류 취합·회수 독촉

- **목적:** 보냈거나 받아야 할 서류가 돌아오지 않은 것을 찾아 알려 준다.
- **시작 조건:** `DOC_COLLECTION`. 받아야 할 서류의 수집·반환·독촉이 해당하고, 문서 작성·송부는 `CONTRACT_PREP`이다.
- **알림:** 서류 발송일 기준 D+7, D+14. 발송일을 모르면 "발송일 확인 필요"로 표시한다.
- **멈추는 조건:** 상대방에게서 관련 메일이 오면 "완료로 옮길까요?"를 제안한다 (`taskstatus` 규칙 재사용). 자동으로 완료하지 않는다.
- **필요한 데이터:** 할 일, 상대방, 주고받은 메일. **지금 있다.** 첨부 파일이 실제로 왔는지는 확인하지 못한다.
- **준비 체크리스트 (초안)**
  - 받아야 할 서류 목록 확인
  - 마지막으로 요청한 날짜 확인
  - 받은 메일에 해당 서류가 있는지 확인
- **산출물:** 미회수 안내, 독촉 메일 초안 (발송 대기함까지).
- **사람이 정하는 것:** 독촉 여부, 문구, 발송.
- **회사 확인:** 독촉 간격, 서류 종류 목록.

## S-08 종료 평가 작성

- **목적:** 투입이 끝날 때 평가를 빠뜨리지 않게 한다.
- **시작 조건:** `END_EVALUATION`. 인력 투입·프로젝트 종료 평가만 해당하고, 월간 영업 성과 평가는 `NONE`이다.
- **알림:** 투입 종료일 당일 (D-0).
- **필요한 데이터:** 투입 종료일, 투입 인력, 평가 양식, 관련 회의록. **종료일·인력·양식은 지금 없다.**
- **준비 체크리스트 (초안)**
  - 투입 기간과 역할 확인
  - 해당 기간의 회의록에서 고객 의견 모으기
  - 평가 양식 항목 확인
- **산출물:** 회의록에서 모은 근거 목록. **평가 점수나 평가 문장은 AI가 정하지 않는다.**
- **사람이 정하는 것:** 평가 내용 전부.
- **회사 확인:** 평가 양식, 평가 결과의 공개 범위.

## S-09 수익성 검토

> **학생 범위 밖.** 회사의 단가·원가가 필요해 명세만 남기고, 가짜 숫자로도 계산 기능을 만들지 않는다.

- **목적:** 조건 협의 전에 마진을 확인하도록 알린다.
- **시작 조건:** `PROFITABILITY_REVIEW`. 마진·마진율·수익률 계산이 해당한다.
- **알림:** 조건 협의 일정 전. 며칠 전인지는 회사와 정한다.
- **필요한 데이터:** 단가, 원가, 수수료, 회사 마진 기준. **모두 없다.**
- **준비 체크리스트 (초안)**
  - 협의할 조건 확인
  - 회사 마진 기준 확인
  - 담당 부서의 검토 필요 여부 확인
- **산출물:** "수익성 검토가 필요하다"는 안내만. **금액·마진을 계산하거나 추측하지 않는다.**
- **사람이 정하는 것:** 계산과 판단 전부.
- **회사 확인:** 이 서비스를 쓸지, 쓴다면 자료 제공 방식과 접근 권한.

## S-10 신규 인력 소싱 착수

- **목적:** 인력 요청이 들어오면 후보 탐색을 늦지 않게 시작하게 한다.
- **시작 조건:** `SOURCING_START`. 인력 후보 탐색 착수만 해당하고, 공급업체·자재 탐색은 `NONE`, 찾은 후보 제출은 `PROPOSAL_SUBMISSION`이다.
- **알림:** 인력 요청일로부터 1영업일 안의 아침 묶음. **주말은 규칙으로 뺄 수 있지만 공휴일·회사 휴무일 목록은 아직 없다.**
- **필요한 데이터:** 요청 내용(직무·인원·시기), 고객, 원문 근거는 회의록·메일에 있다. **후보 풀은 없다.**
- **준비 체크리스트 (초안)**
  - 요청 직무·경력·인원 확인
  - 투입 희망 시기와 근무 조건 확인
  - 빠진 조건을 고객에게 물어볼 질문 정리
- **산출물:** 요청 조건 요약 (출처 표시), 빠진 조건 목록.
- **사람이 정하는 것:** 탐색 경로, 후보 선정, 연락.
- **회사 확인:** 후보 풀과 채용 채널, 영업일 기준.

## 구현할 때 먼저 합의할 것

1. **계약·투입 인력 데이터:** S-04·S-08에 필요하다. `person.schema.json`에는 계약 인력 구분과 계약 기간이 없어 `[contract]` 변경이 필요하다.
2. **발송 대기함:** S-05·S-06·S-07의 메일 초안에 필요하다. 아직 없고 담당도 정해지지 않았다.
3. **서비스별 기준일:** `task.schema.json`에는 `dueDate`만 있다. 계약 종료일·서류 발송일을 어디에 둘지 정해야 한다.
4. **회사 자료:** 준비 체크리스트, 서류 목록, 평가 양식, 휴무일, 단가 기준.
