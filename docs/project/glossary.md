# 용어

| 용어 | 뜻 |
| --- | --- |
| 일정관리 에이전트 | "기록 담당". 접촉을 회의록·할 일로 바꾸고 캘린더·세일즈맵에 등록 |
| 고객지원 에이전트 | "준비 담당". 할 일 종류에 맞는 준비 안내를 때맞춰 보냄 |
| 상대 식별 (개체 연결) | 메일의 A씨와 대장의 A씨가 같은 사람인지 가리는 것. 3단 판정: 확정 / 후보 / 신규 |
| 사람 확인 관문 (Human Gate) | AI 결과를 사람이 확인하기 전엔 확정하지 않는 지점. 식별 병합, 회의록·할 일 확정, 외부 발송 |
| 발송 대기함 | 외부로 나갈 메시지를 쌓아 두는 곳. 실제 발송은 사람이 누른다 |
| 기준 모델 (baseline) | 규칙·유사도로 만든 단순한 판정기. 학습 모델은 이것을 이겨야 교체된다 |
| 정밀도 / 재현율 | 맞다고 한 것 중 실제로 맞은 비율 / 실제 정답 중 찾아낸 비율. 식별은 정밀도를 더 중시 (잘못 합치면 되돌리기 어려움) |
| 확률 보정 | 모델이 "0.9"라고 하면 실제로 10번 중 9번 맞도록 맞추는 것. 3단 판정의 경계값을 정할 때 필요 |
| 인물 단위 분할 | 학습·평가 데이터를 나눌 때 같은 인물이 양쪽에 섞이지 않게 하는 것. 섞이면 점수가 거짓으로 높아짐 (데이터 누수) |
| F1 / 부류별 F1 평균 | 정밀도·재현율의 조화 평균 / 11부류 각각의 F1을 단순 평균. 드문 부류도 챙기는지 봄 |
| 제로샷 | 예시 없이 설명만 주고 LLM이 판정하게 하는 것. ML-2의 비교 기준 |
| 지식 증류 | 큰 모델(LLM)이 만든 데이터로 작은 모델을 학습시키는 것. ML-2 비교 실험의 핵심 |
| 리드타임 | 준비에 걸리는 기간. 며칠 전에 알릴지 정하는 기준 |
| 아침 묶음 브리핑 | 그날 알릴 것을 아침 한 통으로 묶어 보내는 것. 개별 알림 대신 기본값 |
| 회사 요청 ①~⑤ | 회사 담당자가 요청한 기능 5개: ① 미팅 정리 ② 할 일·담당·기한 ③ 사람별 이력 ④ 진행 상태·알림 ⑤ 다음 미팅 준비 (`overview.md`) |
| 확인 화면 | 원문·회의록·할 일을 한 화면에서 고치고 확정하는 화면 (`screens.md` ③). 사람 확인 관문의 실제 화면 |
| 확인 대기함 | 아직 확정 안 된 회의록·할 일·식별 후보를 모아 보는 메뉴 (기존 "처리 이력" 자리) |
| 메일플러그 | 회사가 쓰는 메일 서비스. IMAP으로 메일을 가져온다 (`mailplug.md`) |
| IMAP / POP3 | 메일을 가져오는 표준 방식. IMAP은 폴더(보낸편지함 포함)를 볼 수 있고 읽음 표시를 안 바꾸고 읽을 수 있음. POP3는 받은 메일함만 |
| 앱 비밀번호 | 외부 프로그램 접속용으로 따로 발급하는 비밀번호. 레포·채팅에 절대 올리지 않는다 |
