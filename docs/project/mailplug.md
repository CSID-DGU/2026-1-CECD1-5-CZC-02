# 메일플러그 연동 (검토 결과 · 담당: 개발 총괄)

> 2026-10-13 검토, 회사에 공유함 (D-014). 테스트 계정은 받았고, 개통일·관리자 설정은 회사 회신 대기.
> **계정·앱 비밀번호는 레포·채팅·프롬프트에 절대 넣지 않는다.** 로컬은 환경 변수, 서버는 암호화 저장.

## 결론

**IMAP으로 가능.** 웹훅·MCP가 없어도 된다. 지금 수집은 이미 **주기적으로 가져오는 방식**(`AutoPipelineService`, `auto.pipeline.interval-ms` 기본 45초)이라, 메일 가져오는 부분만 IMAP으로 추가하면 된다.

**Gmail을 없애지 않고 메일플러그를 추가**한다. 캘린더 등록(`GoogleCalendarEventService`)이 Gmail 연결 때 받은 Google 토큰(`GmailIntegrationService.getValidAccessTokenForUser`)을 쓰므로, Google 연결을 끊으면 캘린더·Salesmap 반영도 끊긴다.

```
메일플러그 (IMAP, 읽기 전용) ─┐
Gmail (선택)               ─┴─▶ 우리 서버 ─▶ AI 분석·사람 확인 ─▶ Google Calendar (Google 계정 연결 유지) ─▶ Salesmap TODO
```

## 확인한 사실

| 항목 | 내용 |
| --- | --- |
| 서버 | 받는 메일 `imap.mailplug.co.kr` (POP3 `pop3.mailplug.co.kr`), 보내는 메일 `smtp.mailplug.co.kr`. 포트는 회사 계정으로 확인 |
| **IMAP 제한** | 2025-04-01 이후 개통 서비스는 IMAP 이용 제한 → **개통일 확인 필수** (회사 회신 대기) |
| 사용 설정 | 신규 계정은 꺼져 있음. 관리자가 IMAP/SMTP를 켜야 하고 계정별로 막을 수도 있음 |
| 비밀번호 | 일반 비밀번호가 아니라 **앱 비밀번호** |
| 자동 해제 | 30일간 사용 기록이 없으면 자동으로 꺼짐 → 오래 멈췄다 다시 쓰면 다시 켜야 함 |
| POP3 한계 | 받은 메일함만. 보낸 메일 못 봄 |

## 구현 방향

| 항목 | Gmail (지금) | 메일플러그 (IMAP) |
| --- | --- | --- |
| 로그인 | Google OAuth | 메일 주소 + 앱 비밀번호 입력, 서버에 **암호화 저장** |
| 새 메일만 | 마지막 동기화 시각 | 메일함별 UIDVALIDITY + 마지막 UID 기억 |
| 대화 묶기 | Gmail 스레드 ID | `Message-ID` / `In-Reply-To` / `References` 머리글로 직접 묶기 |
| 읽음 표시 | — | `EXAMINE`(읽기 전용) + `BODY.PEEK[]`로 가져와 **읽음 표시를 바꾸지 않음** |
| 보낸 메일 | 가능 | 보낸편지함 폴더도 수집 (POP3면 불가) |
| 발송 | — | 이번 범위 아님 (발송 대기함까지만) |

- 저장은 기존 `source` 테이블을 그대로 쓴다 (`sourceType=EMAIL`). 어느 계정에서 왔는지 구분할 값이 필요하면 담당자와 상의 후 추가.
- 설정 화면: 메일 계정을 **Gmail / 메일플러그 / 둘 다** 중 선택, 계정별 자동 수집 on/off. Google 계정은 "캘린더 연결"로 따로 표시.
- 테스트는 네트워크 없이: IMAP 클라이언트를 인터페이스로 감싸고 가짜 구현으로 단위 테스트. 실제 접속 테스트는 기본값으로 끄기.
- 계정이 늦게 오면 다른 테스트용 IMAP 메일함으로 먼저 개발하고, 받으면 서버 주소만 바꾼다.

## IMAP을 못 쓰는 계정이면

1. **POP3로 받은 메일만** — "답장 안 한 메일", "우리가 보내기로 한 약속 이행" 확인이 약해짐
2. 담당자가 보내는 메일에 수집용 주소를 숨은 참조(BCC) — 사람이 매번 해야 함
3. 메일플러그 자동 전달로 테스트 메일함에 복사 — 회사 보안 정책 확인 필요
