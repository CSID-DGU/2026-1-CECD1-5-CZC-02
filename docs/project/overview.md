# 2학기 최종 목표 (한 페이지 요약)

> 기업 멘토의 과제 정의서(v0.2)를 우리 말로 정리한 것. 원본은 사내 문서라 레포에 넣지 않는다.
> 세부 결정이 바뀌면 이 파일이 아니라 `decisions.md`에 먼저 기록하고, 큰 방향이 바뀔 때만 이 파일을 고친다.

## 한 문장

영업 담당자가 사람을 만나고 나면, **AI가 회의록을 쓰고 · 할 일을 뽑고 · 할 일 날짜가 다가오면 준비물까지 알려주는** 두 개의 에이전트를 만든다.

## 해결하려는 문제

1. 만난 내용이 기록되지 않는다 (미팅록 생성률 0%)
2. 상대가 누군지 기억하지 못한다 (다채널 접촉, 동명이인)
3. 할 일이 머릿속에만 있다
4. 일마다 준비물이 다른데 매번 처음부터 찾는다

## 회사가 요청한 기능 5개 (2026-10-13 · 1순위)

과제 정의서와 별도로 회사 담당자가 요청한 기능. 정의서의 핵심 부분과 같고, **11/30 실사용 버전에 반드시 들어간다** (D-013).

| 요청 | 우리 기능 | 담당 |
| --- | --- | --- |
| ① 미팅 내용 등록·정리 | 메모·메일 → 표준 회의록, 확인 화면 | B |
| ② 할 일·담당자·기한 추출 | 회의록 → 할 일 (무엇을·누가·언제까지) | C |
| ③ 고객·계약 인력별 미팅 이력 | 상대 식별 + 사람별 이력 화면 | A |
| ④ 할 일 진행 상태·사전 알림 | 상태 관리·자동 변경 제안, 아침 묶음 알림 | C(상태), D(자동 변경·알림) |

화면 시안 6개와 담당은 [`screens.md`](screens.md).

## 두 에이전트

```
메일·메모 ───▶ ① 일정관리 에이전트 (기록 담당)
                   상대 식별(A) → 회의록(B) → 할 일 뽑기(C) → [사람 확인] → 캘린더·세일즈맵 등록(D)
                                                                      │ 할 일 목록
                                                                      ▼
                  ② 고객지원 에이전트 (준비 담당)
                   할 일 종류 판정(C) → 언제 알릴지 계산 → 자료 수집 → 준비 안내(D) → 아침 묶음 브리핑(D)
```

- **가장 중요한 부품은 상대 식별.** 틀리면 뒤가 전부 틀린다.
- 준비 서비스 10종 중 **3종만 실제 구현**: **S-01 미팅 전날 브리핑(먼저, 회사 요청 ⑤)**, 그다음 S-02 출장 준비, S-03 계약 서류 대조 (D-016). 나머지 7종은 명세서만.
- 녹음 → 텍스트(STT)는 **추가 검토** (D-015). 텍스트 메모 입력이 먼저.

## 머신러닝

| 코드 | 내용 | 담당 |
| --- | --- | --- |
| ML-1 | 두 인물 기록이 같은 사람일 확률 (로지스틱 회귀 → 그래디언트 부스팅) | A |
| ML-2 | 할 일 문장 → 11부류 분류 (문장 임베딩 + 로지스틱 회귀) | C (LLM 직접 판정 비교는 B) |
| ML-3 | 회의록 문항 교차 검증 — **이번엔 하지 않음** | — |
| ML-4 | 사람 수정 기록 (모델 아님, 정답 공급원) | D (API) + A·B·C (호출) |

원칙: **규칙·유사도로 만든 기준 모델을 먼저** 세우고, 학습 모델은 **기준을 이길 때만** 교체한다. 지면 기준을 유지하고 왜 졌는지 기록한다.

## 절대 규칙

1. **진짜 고객 데이터를 쓰지 않는다.** 가짜·가명 데이터와 테스트 계정만. LLM 프롬프트에 실제 이름 금지. 키·비밀번호 커밋 금지.
2. **AI가 혼자 확정하지 않는다.** 식별 병합·회의록·할 일은 사람이 확인 후 확정. 외부로 나가는 메시지는 **발송 대기함까지만**.
3. **알림은 하루 1회 묶음 + 즉시 알림 3건 이내.** 넘으면 다른 목표를 다 달성해도 실패.
4. **모르면 비워 둔다.** 추측으로 칸을 채우지 않고, 채운 내용엔 원문 근거를 붙인다.
5. **규칙으로 되는 건 LLM을 쓰지 않는다.** 날짜 계산·상태 변경·기한 판정은 규칙.

## 완료 기준

| 지표 | 목표 |
| --- | --- |
| 상대 식별 | 확정 판정 정밀도 ≥ 95%, 후보 3건 내 재현율 ≥ 90% |
| 회의록 생성률 | 0% → 시범 운영 기간 80% 이상 |
| 회의록 확인 시간 | 건당 3분, 다인 방문 인당 30초 이내 |
| 할 일 추출 | 명시적 약속 재현율 ≥ 90% |
| ML-2 | 부류별 F1 평균 ≥ 0.80, '해당 없음' 재현율 보고 |
| ML-4 | 사람 수정 기록률 100% |
| 알림 | 1일 1회 묶음 + 즉시 3건 이내 |
