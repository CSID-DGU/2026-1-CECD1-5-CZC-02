## 2. 필수 vs 확장

**필수** = 11/30 실사용 버전에 반드시 들어가는 것 (회사 요청 5개, D-013) + 지켜야 할 원칙. **확장** = 필수가 돈 뒤에 프로젝트를 풍부하게 하는 것. 학습 모델은 기준(규칙)을 이길 때만 교체한다.

| 구분 | 기능 | 담당 | 상태 |
| --- | --- | --- | --- |
| 필수 ① | 미팅 정리: 메모·메일 → 표준 회의록, 3단 확인 화면 | B | ✅ |
| 필수 ② | 할 일·담당·기한 추출, 하나씩 확정 | C | ✅ |
| 필수 ③ | 사람별 미팅 이력: 상대 식별 + 이력 화면 | A | 🔄 식별 API까지, 인물 대장·연결 남음 |

## 3. 기존 방식과 무엇이 다른가 (비교표)

> 2026-11-09 방식별 대표 제품 2~3개의 공식 문서(기능 소개·도움말·가격·보안 문서)로 확인한 일반적인 모습. 제품 이름과 칸별 출처는 발표 자료에서만 쓴다. "—"는 문서에서 확인하지 못했다는 뜻이다.

| | 수기 메모 + CRM 직접 입력 | 녹음 기반 AI 회의록 도구 | CRM 내장 AI | 범용 AI 비서 | **우리** |
| --- | --- | --- | --- | --- | --- |
| 입력 | 사람이 전부 입력 | 녹음, 화상 회의 봇 | CRM 기록, 통화 녹음, 메일·일정 자동 수집 | 붙여넣기, 회의 녹음, 메일 | 미팅 메모·메일 (녹음 없음) |
| 상대가 누구인지 | 사람 기억 | 목소리 학습, 메일 주소로 CRM 연락처와 맞춤. 못 찾으면 건너뛰거나 새로 만듦 | 메일 주소로 맞춤. 여럿이면 규칙으로 하나를 자동 선택하거나 새 연락처를 만들고, 중복은 나중에 사람이 병합 | 거의 없음 ("화자 1"식 표시) | **이름·연락처·소속을 함께 비교, 동명이인이면 자동으로 고르지 않고 후보 3명 → 사람이 고름** |
| 회의록 항목 근거 | — | 원문 시점과 연결 (일부) | 제안마다 원문 구간 표시 (일부) | 일부 출처 표시 | **항목마다 원문 문장, 모르면 빈 칸** |
| 할 일·기한 | 사람이 정리 | 할 일·담당 추출, 기한은 대화에 나올 때만 | 다음 단계 제안, 기한 자동 계산은 — | 할 일 제안, 기한은 사람이 입력 | 무엇을·누가·언제까지, **기한은 규칙으로 계산** |
| 준비 안내 | — | 회의 전 브리핑 (일부 제품) | 미팅 준비 요약·안건 | 회의 준비 요약 (일부) | **할 일 11부류 판정 → 종류별로 무엇을 언제 준비할지 안내** (이번 학기 S-01 등 3종 구현) |
| 확정 | 사람 | CRM 자동 동기화가 기본인 곳이 많음 (검토 후 보내기 옵션이 생기는 중) | 활동은 자동 기록, AI 제안은 하나씩 승인 또는 자동 승인 선택 | 자동 저장·공유하는 곳과 사람이 저장하는 곳이 섞임 | **모든 항목을 사람이 하나씩 확정, 고친 값은 수정 기록** |
| 데이터가 회사 밖으로 | 안 나감 | 나감 (클라우드). 일부는 개인정보를 지운 데이터를 자체 학습에 사용 | 나감 (클라우드). 외부 LLM 학습은 막지만 자체 모델 학습은 설정에 따름 | 나감 (클라우드). 기업 요금제는 학습에 쓰지 않음 | **안 나감 (로컬 LLM)** |
| 추가 비용 (인당 월) | 입력 시간 | 무료 ~ 약 $30 | CRM 요금제 + AI (약 $90 이상) | 약 $14~25 | 무료 모델 (PC 자원) |
| 쓸수록 나아지나 | — | 화자 교정을 학습 | 좋아요·싫어요 피드백, 자체 모델 학습 | 메모리·지침 | **사람이 고친 기록이 재학습 정답** |
| **그쪽이 앞서는 점** | 도구 없이 바로 | 음성을 그대로 받음, 다국어, 완성된 앱 | CRM과 깊은 연동, 규모·보안 인증 | 범용 지능·검색, 이미 쓰는 업무 도구 안 | — |

**과장하지 않기:** 상대 식별·근거 연결·사람 확인·회의 전 브리핑 자체는 다른 도구에도 있다. 우리 차별점은 ① 녹음 없이 메모·메일로 시작 ② 여러 단서로 비교하고 동명이인은 사람이 고름 ③ 할 일 종류별 준비 안내와 규칙 기한 ④ 모든 항목을 근거와 함께 하나씩 확정하고 고친 기록을 재학습에 씀 ⑤ 데이터가 회사 밖으로 나가지 않음이다. "다른 도구는 데이터를 학습에 쓴다"는 기업 요금제에는 대부분 맞지 않다.

발표 문장: "회의록을 만들어 주는 도구는 많지만, 저희는 녹음 없이 메모와 메일로 시작하고, 동명이인까지 후보를 보여 줘 사람이 고르게 하며, 할 일을 업무 종류별 준비 안내로 이어 줍니다. 모든 항목은 원문 근거와 함께 사람이 확정하고, 데이터는 회사 밖으로 나가지 않습니다."

## 4. 새 회사에 도입할 때 설정할 것

| 항목 | 지금 | 회사마다 바꿀 것 | 바꾸는 방법 |
| --- | --- | --- | --- |
| 메일 계정 | Gmail 연결 있음, 메일플러그 예정 | 회사 메일 서버, 관리자의 IMAP 허용, 앱 비밀번호 | 설정 화면 (메일 계정) |
| 캘린더 | Google 계정 연결, 기본 캘린더·서울 시간대 | 쓸 캘린더 | 설정값 (`GOOGLE_CALENDAR_ID` 등) |
| CRM (세일즈맵) | 연결 주소 설정값, 지금은 모의 모드 | 회사 CRM 주소·인증 | 설정값 (`SALESMAP_API_*`) |
| 회의록 양식 | 5문항 + 경량 3필드 고정 (D-009) | 회사 회의록 양식 | **코드·데이터 형식 변경 필요** (팀 합의) |
| 할 일 부류 | 11부류. S-04~S-10은 인력 파견 업무 전용 | 업종에 맞는 부류만 쓰기·추가 | **지금은 규칙 코드**. 켜고 끄는 설정 필요 |
| 인물 대장 | 비어서 시작 | 기존 고객 명단 가져오기 | 없음 (가져오기 기능 필요) |
| 알림 | 하루 1회 묶음 | 브리핑 받을 시간 | 설정 화면 (알림 시간, 예정) |
| LLM | `qwen2.5:7b` (RAM 약 4.7GB) | PC 사양에 맞는 모델 | 설정값 (`OLLAMA_MODEL`, 부족하면 3b) |
| 사용 범위 | 담당자별 분리 (D-025⑤) | 팀 공유·담당자 이관 여부 | 시범 운영 전 회사와 결정 |

**정리:** 대부분은 설정값과 연결 화면으로 끝난다. 회사마다 코드를 고쳐야 하는 것은 **회의록 양식**과 **할 일 부류** 두 가지라서, 시범 운영 전에 회사 양식·업무 목록을 받아 맞춘다.

## 5. LLM 모델에 묶여 있지 않은가

- 모델은 설정값 하나(`OLLAMA_MODEL`)로 바꾼다. 같은 평가셋·같은 코드로 로컬 모델 4종을 돌려 모두 동작했다 (LLM 성공률 100%, [`MODELS.md`](../../ai-module/eval/MODELS.md)).
- 점수는 과제마다 1등이 달랐다: 메일 분석은 `qwen2.5:7b` 81.0%, 회의록은 `gemma4:e4b` F1 83.8%. 두 과제를 다 이기지 못해 기본값을 유지했다 (D-027).
- 모델이 실패해도 멈추지 않는다: 메일 분석은 규칙 결과로 돌아가고, 회의록은 빈 초안 + 실패 이유를 보여 사람이 쓴다.
- 날짜·기한·상태처럼 규칙으로 되는 것은 LLM을 쓰지 않아 모델과 무관하다 (규칙 4).

## 6. 데이터 결정을 사용자가 전권으로 갖는가

예. 데이터 상태를 바꾸는 결정(확정·병합·신규 등록·보관·삭제)은 **사용자가** 하고, 에이전트는 제안만 한다. 원본·확정본은 "삭제"해도 숨김(보관)만 하고, 사람의 결정은 수정 기록 또는 누가·언제 기록으로 남는다. 자세히 D-025·D-026.

## 7. 사람 확인(human-in-the-loop) 성능 평가 계획

| 지표 | 무엇을 보나 | 데이터 | 상태 |
| --- | --- | --- | --- |
| 무수정 승인률 | AI 초안을 고치지 않고 승인한 비율 (에이전트·항목별) | 수정 기록 (`ACCEPTED` vs `EDITED`) | 기록은 쌓이는 중, 집계 필요 (D) |
