# 이력서 추출 평가

`app/resumes/`(이력서 → `resume_profile`)가 얼마나 정확한지 재는 곳. **규칙만 · 로컬 LLM만 · 섞은 방식(기본)** 을 같은 자료로 비교한다.

## 파일

| 경로 | 내용 |
| --- | --- |
| `dev/cases.json` | 가짜 개발셋 8건 (워드 표 모양 `blocks` 또는 줄글 `text` + 정답 `gold`). 사람·회사 이름은 전부 지어낸 것 |
| `score.py` | 채점 (칸별 정확도, 프로젝트 수, 기술 재현율·정밀도, 산업 재현율, 총 경력 오차, 근거가 원문에 있는 비율, 건당 시간) |
| `run.py` | 세 방식을 돌려 비교. 실제 이력서는 레포 밖 폴더를 받아 **숫자만** 출력·저장 |

| 케이스 | 상황 |
| --- | --- |
| d01 | 개인이력카드 모양 — 두 줄 머리글(개발분야=산업·응용, 개발환경=기종·OS·언어·DBMS·TOOL·기타), 두 줄짜리 프로젝트, 겹친 기간, 진행 중 |
| d02 | 한 줄 머리글, 개발환경 한 칸에 빗금으로 여러 기술, 두 자리 연도, 값이 칸 이름 아래 |
| d03 | 참여기간이 시작일·종료일 두 칸, 종료일 "현재", 등급 칸 |
| d04 | 프로젝트 표가 쪽 나눔으로 두 표로 나뉨 (둘째 표에 머리글 없음) |
| d05 | 다른 표 — 경력 표·보유 기술 표만 (총 경력은 근무 기간으로) |
| d06 | 줄글 경력기술서 — 보유 기술 줄, 경력 2곳, 프로젝트 2개(하나 진행 중) |
| d07 | 줄글 — 특급 기술자, 자격증, 문장 속 프로젝트 |
| d08 | 다른 표 — 프로젝트마다 "칸 이름 \| 값" 세로 표 |

## 정답 쓰는 법

```json
{"format": "TABLE_CARD", "name": "가상인", "birthYear": 1991, "grade": "INTERMEDIATE",
 "projectCount": 5, "skills": ["Java", "Oracle"], "industries": ["금융"],
 "totalCareerMonths": 57, "availableFrom": "2027-02-01"}
```

- 이력서에 없는 값은 `null`(목록은 `[]`). 등급은 적혀 있을 때만, 생년은 생년월일·출생 연도가 적혀 있을 때만.
- `skills`는 기술명 사전(`app/resumes/dictionary.py`)의 통일 이름 중 이력서에 나온 것. 사전에 없는 기술은 넣지 않는다.
- `industries`: 표 양식은 개발 분야(산업) 칸에 적힌 것만, 줄글·다른 표는 고객사·프로젝트 이름에 산업 낱말(은행·전력·물류 …)이 있는 것.
- `totalCareerMonths`: 프로젝트 기간을 달 단위로 합치되 겹친 달은 한 번만, 시작·끝 달 포함, 진행 중이면 기준일(2026-11-24)의 달까지. 프로젝트 기간이 하나도 없으면 근무 기간으로.
- `availableFrom`: 진행 중 프로젝트의 종료 달 다음 달 1일. 진행 중이 없거나 종료일이 없으면 `null`.

## 돌리는 법 (ai-module 폴더에서)

```bash
python -m eval.resumes.run --modes rule          # 규칙만 (Ollama 없이, 몇 초)
OLLAMA_SEED=42 python -m eval.resumes.run        # 세 방식 (로컬 Ollama 필요)
OLLAMA_MODEL_RESUME=qwen2.5:7b OLLAMA_SEED=42 python -m eval.resumes.run --modes llm,hybrid
```

## 실제 이력서 평가 (개인정보)

- 실제 이력서와 정답은 레포 밖 `.private/resumes/`에만 둔다. 파일명·이름·내용을 커밋·PR·메시지에 넣지 않는다.
- 실제 이력서는 **로컬 Ollama로만** 처리한다. 엔진은 공용 router를 쓰지 않고 Ollama만 부른다.
- 규칙·프롬프트를 고칠 때는 이 개발셋(가짜)만 본다. 실제 이력서는 고친 뒤 마지막에 재기만 한다(점수 부풀림 방지).
- `run.py --docx-dir …`는 건수·비율만 출력하고, 프로필 내용은 저장하지 않는다. 정답이 없으면 정답 없이 셀 수 있는 지표(채운 비율·근거 대조율·시간)만 낸다. `--pseudo-gold-rule`은 표 양식에서 규칙 결과를 기준으로 LLM이 얼마나 같은지 잰다(정답이 아니라 일치율).
