# 규칙 + 로지스틱 후보 검색

`POST /identity/resolve`의 기본 처리를 `hybrid.py`로 연결했다. JSON 요청·응답 계약과 경로는 그대로다. `engine.resolve_identities`는 순수 규칙 비교·폴백·기존 실험 재현용으로 유지한다.

## 판정과 순위

1. 입력과 중복 personId를 기존 스키마로 먼저 검사한다. 정보 부족·빈 대장은 규칙 NEW(빈 후보)를 유지한다.
2. 연락처가 유일하게 정확 일치하고 기존 `_can_confirm`의 이름·소속·다른 연락처 충돌 검사를 통과하면 기존 RULE/CONFIRMED를 반환한다. score는 null이다. 모델이 확정 판단에 관여하지 않는다.
3. 나머지는 원문을 보존한 비교 결과의 14개 단서를 고정 로지스틱으로 평가한다. 이름 유사도는 기존 레벤슈타인 기반이다. 이름/연락처 정확 일치 후보는 낮은 모델 점수로 제거하지 않는다. 그 밖에는 보정 점수 .02 이상을 포함한다.
4. 연락처 일치 여부 → 정확 이름 일치 여부 → 모델 점수 → 동점 personId 순으로 최대 3명을 제시한다. 각 모델 점수의 소수점 12자리에서 순위를 비교해 BLAS와 순수 Python 간 약 1e-16 계산 차이를 우열로 취급하지 않는다. 응답 score는 원래 보정값이며, 수치상 동점인 일부 불필요 후보의 ID는 원 실험과 달라질 수 있다. 전체 평가 지표 유지도 별도로 검사한다.
5. 후보가 있으면 MODEL/CANDIDATES, 없으면 MODEL/NEW다. personId는 null이다. 신규 등록·병합·사람 선택·Revision 저장 흐름은 기존 호출자가 수행한다. 후보가 넘치면 첫 후보의 reasons에 전체 후보 수·직접 검색 안내를 한 번 남긴다. 화면은 이를 후보 목록 위에 한 번 표시한다. 후보별 비교 근거는 그대로다.

혼합 검색은 기존 규칙의 **연락처·정확 이름 보호**와 학습 후보 검색을 결합한다. 기존 fuzzy(.88)+회사 규칙의 모든 후보를 무조건 합집합으로 넣는 방식은 아니다. 새 표기에서 과거 fuzzy 후보보다 항상 넓은 집합이라는 보장은 없다. 후보 누락 감소와 불필요 후보 증가는 [새 평가](../../ml/identity/FRESH_VALIDATION.md)를 참고한다.

## 점수와 계수 출처

`logistic_v1.json`: 원 controlled_v1 실험의 seed 42·C=10 모델, 원 fit 인물과 원 calibration 인물만 사용했다. 독립 튜닝 단계에서 선택된 .02를 유지했다. 새 검증 자료로 재학습하거나 임계값을 바꾸지 않았다. sourceReportSha256과 학습 범위를 JSON에 기록했다.

MODEL score는 별도 합성 calibration 자료에서 sigmoid 보정한 수치다. **실제 업무에서 같은 사람일 확률이 그대로 보장된다는 뜻은 아니다.** .02도 자동 확정 기준이 아니라 후보 누락을 줄이기 위한 실험상 기준이다. 화면은 reasons와 사람 선택을 중심으로 사용한다. RULE score는 여전히 null이다.

운영 추론은 표준 Python으로 평균·스케일·로지스틱 계수·보정 계수를 계산한다. pickle·joblib·sklearn·numpy·모델 다운로드·외부 API가 필요 없다. 수치 계수와 모델 메타데이터만 저장하고 학습 인물·연락처는 운영 모델에 포함하지 않는다.

## 실패 처리와 전환

모델 파일 누락·무결성/형식 오류·추론 오류이면 기존 규칙으로 처리하고 고정된 경고 문구만 기록한다. 입력 인물 정보나 계수를 로그에 출력하지 않는다. 모델은 프로세스에서 한 번 로드하므로 교체 시 AI 서버를 재시작한다.

기본은 hybrid다. 즉시 규칙 모드로 실행하려면 AI 서버 터미널에서:

```bash
IDENTITY_CANDIDATE_MODE=rule python -m uvicorn app.main:app --port 8000
```

혼합 모드:

```bash
IDENTITY_CANDIDATE_MODE=hybrid python -m uvicorn app.main:app --port 8000
```

실행 중인 서버에 이 코드 변경이 자동 반영됐다고 가정하지 않는다. 기존 명령에 `--reload`가 없었다면 해당 AI 서버만 재시작한다. DB·프론트 재시작은 이 변경에 필요 없다.

## 검사·내보내기

`test_hybrid.py`는 실제 main 라우트의 오타 복구·계약 응답, 높은 점수로도 확정 금지, 공유/충돌 연락처 보존, 모델 오류 폴백, 모델 JSON 검사, 런타임 특징과 학습 특징 일치, 동점 순위, 원·새 전체 자료 평가 지표 유지를 확인한다. 기본 테스트는 학습·네트워크를 사용하지 않는다.

원 학습 환경에서 계수 재현(기존 출력 덮어쓰기 금지):

```bash
python -m ml.identity.export_logistic --output /tmp/identity-logistic-export.json
```

원 코드·자료 해시와 sklearn 버전이 일치해야 한다. 내보내기에서 sklearn과 순수 Python의 보정값 최대 차이는 6.66e-16이었고 원 평가도 재현됐다. 실행 시 새 JSON을 운영 경로로 자동 설치하지 않는다.

이번 변경은 A의 `app/identity/`, `ml/identity/`에만 있다. contracts·공용 라우트 등록·다른 담당 코드는 변경하지 않았다. 데이터셋은 합성이며 동명이인 4명·심하게 훼손된 이름 등에서는 직접 검색과 추가 단서가 필요하다. 이 코드 연결을 실제 사용자 데이터의 성능 검증으로 해석하지 않는다.
