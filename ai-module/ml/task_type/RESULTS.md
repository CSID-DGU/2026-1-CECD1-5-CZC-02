## 같은 평가 55개로 비교

사용자 전달 피드백에 따르면 평가 라벨 55개는 교차 검수에서 모두 일치했다. evaluation.json은 바이트 변경 없이 그대로 보존했다.
이 평가 문장과 오류가 개발 피드백으로 사용됐으므로 독립 최종 평가셋으로 주장하지 않는다. 이름을 가린 회사 문장을 받으면 별도 최종 평가 전용으로 추가한다.

기본 학습 조건은 같은 다국어 MiniLM 임베딩·정규화·seed=42·max_iter=2000·class_weight=None을 유지했다.
부류 불균형을 확인한 뒤 평가 결과를 보기 전에 balanced 가중치 진단을 추가하겠다고 명시했다. 같은 임베딩으로 두 조건을 비교했고 정규화 강도/임계값을 평가 점수에 맞춰 검색하지 않았다.
가중치 저장 후 예측 재현도 검사했다. 학습 가중치는 로컬 .npz이고 git에는 포함하지 않는다.

**운영은 RULE 유지.** 학습 모델은 정정 후 오히려 점수가 낮아졌으며 불균형 보정도 기준을 이기지 못했다.
소싱 재생성·다수 라벨 정정·학습 제외가 함께 바뀌었으므로 이번 비교만으로 변화 원인을 분리할 수 없다.
NONE 209개 대 종료 평가 8개라는 부류 불균형, 개발 직무에 치우친 새 소싱 문장, 반복적인 학습 문체와 평가 문체 차이가 남아 있다.
이것들은 추가 검증할 후보 원인이다. 단순히 공급업체 문장을 고치면 성능이 오른다고 주장하지 않는다.
