## ML-2

학습 후보는 로컬 qwen2.5:7b가 생성한 11부류×60개=660개다. train.json의 모델 digest로
생성 모델을 기록했다. 평가 문장은 별도 작성한 55개이며 학습과 동일 문장/출처/그룹 중복이 없다.
모든 라벨은 PENDING이고, 다른 팀원의 교차 검수는 미완료다.

| 방법 | macro F1 | NONE 재현율 |
| --- | --- | --- |
| 규칙 기준 모델 | 0.962121 | 1.000000 |
| 다국어 MiniLM 임베딩 + 로지스틱 회귀 | 0.446839 | 0.200000 |

**운영은 RULE 유지**. 학습 모델이 기준 모델을 이기지 못했고 데이터 검수도 끝나지 않았다.
가중치 저장 후 예측 재현은 검증했다. 로컬 모델 파일은 git에 넣지 않으며, 재현 명령은 README에 있다.
부류별 점수와 오분류 인덱스는 report.json에 남겼다.

자동 생성 후보에서 경계 오류가 관찰됐다. 예를 들어 DOC_COLLECTION에 '수주 가능 여부 확인',
END_EVALUATION에 '올해의 손익 분석', REJECTION_NOTICE에 '손실 가능 고객에게 다시 연락'이 들어갔다.
이것을 정답 확정본으로 사용하지 않는다. 검수 CSV의 ruleDisagrees는 검토 우선순위를 위한 참고일 뿐,
규칙 모델의 답을 정답으로 강제하는 기능이 아니다.

라벨 잡음과 학습/평가 문체 차이가 성능 저하의 가능한 원인이다. 원인을 분리한 실험은 아직 하지 않았다.
평가셋은 작고 규칙 키워드가 잘 드러나는 합성 문장이어서 높은 규칙 점수도 운영 성능으로 일반화하지 않는다.
다음 개선은 독립 검수·부류 정의 보완·다양한 평가 문장 확보다. 현재 평가 점수에 맞춰 규칙이나
하이퍼파라미터를 반복 조정하지 않았다.

## 추출 평가

엔진 출력에서 복사하지 않고 작성한 합성 회귀셋 31건, 기대 할 일 33개: precision/recall/명시적 약속 recall/기한·종류·약속 구분·상대 ID 정확도는
이 작은 셋에서 모두 1.0이다. B 정답 회의록 10건의 출력 계약/근거 보존 검사도 별도 테스트에 포함했다.
이는 실사용 명시적 약속 재현율 90% 달성이나 목표 완료를 뜻하지 않는다.

평가를 늘리면서 미식별 LIGHT 인물들의 동일 후속이 합쳐지는 문제를 찾아 수정했다.
날짜가 잘못된 입력은 422로 거부하고, 모호한 날짜·조건·복합 종류는 추측하지 않는다.

팀별 연결·검수 요청은 ../../app/tasks/HANDOFF.md를 참고한다.
