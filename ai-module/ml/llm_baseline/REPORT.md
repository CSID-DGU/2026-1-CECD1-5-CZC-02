# ML-2 비교 보고서 — 규칙 vs 임베딩+LR vs LLM 직접 판정 (B, 검수 전)

할 일 문장 하나를 11부류(10부류 + NONE) 중 하나로 고르는 세 방식을 같은 평가셋·같은 지표로 비교했다. **결론은 추천만** 한다. 교체 여부는 11/20 멘토링 때 정한다.

## 한눈에

| 평가셋 | 규칙 | 임베딩+LR | LLM qwen2.5:7b | LLM gemma4:e4b |
| --- | ---: | ---: | ---: | ---: |
| C 평가 55개 (규칙 개발에 쓰임) | **1.000** | 0.306 | 0.982 | 0.913 |
| 새 평가 36개 (모델 실행 전 정답 고정) | 0.316 | 0.259 | 0.844 | **0.931** |

수치는 macro F1. 규칙은 C 55개에서는 완벽하지만, 처음 보는 표현에서는 30개 중 21개를 NONE으로 놓쳤다. LLM은 처음 보는 표현도 잘 맞혔다. 대신 **NONE이어야 할 경계 문장을 억지로 부류에 넣는 경향**이 있다. 이렇게 되면 쓸데없는 알림이 생긴다.

**추천:** 운영은 규칙을 유지한다. LLM은 "규칙이 NONE일 때만 묻고, 결과는 확인이 필요한 추정으로 표시"하는 보조 역할부터 시범으로 붙인다. 근거는 아래에 있다.

## 조건

- **LLM 실행**
  - 로컬 Ollama, `OLLAMA_SEED=42`, temperature 0, JSON 출력 `{"taskType", "reason"}`. gemma4:e4b는 `OLLAMA_THINK=false`. 유료 API는 쓰지 않았다.
  - 형식이 틀리면 NONE으로 두고 실패 건수를 셌다.
  - qwen은 두 번 실행해 91문장 판정이 모두 같았다(재현 확인).
- **지시문**
  - `docs/project/task-types.md`의 정의표와 경계표(D-024)로 만들었다. 지시문 해시는 `995ab78445d9`.
  - 평가 문장은 예시로 넣지 않았다(테스트로 검사).
- **임베딩+LR**
  - C `experiment.py`와 같은 조건이다: MiniLM-L12 다국어, 정규화, seed=42, max_iter=2000, class_weight=None, 학습 656개.
  - 이 PC에서 다시 학습한 예측이 C `report.json`의 55개 예측과 **모두 같아** 재현된 것을 확인했다.
- **시간:** 이 PC의 Ollama는 **GPU를 쓰지 않고 CPU로만** 돌았다. 건당 시간은 이 환경 기준이다.
- **새 평가 36개 (`holdout.json`)**
  - 부류마다 3개, NONE 경계 함정 6개(내부 회의·공급업체 탐색·제출 확인·탈락자 재연락·복합 항목·목적 불명 외근).
  - **어떤 모델도 돌리기 전에 정답을 정해 먼저 커밋**했다(`7118abc`).
  - C 학습·평가·추출 문장 841개, 그리고 지시문에 들어가는 문서 예시와 겹치지 않는다(글자 2-gram 유사도 0.6 미만, 테스트로 검사). 실제로 가장 비슷한 것도 0.35 미만이었다.

- **이 셋은 규칙에 유리하다.** C가 이 55개를 보며 규칙을 고쳤다(C RESULTS.md도 "독립 평가셋 아님"이라고 적음).
- **지시문 누출 1건:** 문서 경계표 예시 "계약 조건별 수익성 분석"과 거의 같은 평가 문장이 1개 있다("계약 조건별 수익성 분석을 수행한다"). 이 문장을 빼고 계산해도 qwen 0.982, gemma 0.913으로 같다(`withoutPromptOverlap`).

  - qwen 1건: "목요일 고객사에 재방문해서 협의한다" → VISIT. 문서 기준은 재방문 = MEETING이다.
  - gemma 4건: 모두 형식 실패다(아래 3-c).

## 3. 틀린 사례 유형

**a. 규칙: 정해진 단어를 벗어난 표현을 놓친다 (21건 → NONE)**

| 놓친 표현 | 규칙이 기다리는 단어 |
| --- | --- |
| "발주처 PM과 정기 미팅" | 고객 |
| "현장 실사" | 현장 방문·점검 |
| "이력서를 묶어서 보낸다" | 제안서·후보 리스트 |
| "떨어진 후보에게 결과" | 탈락·미채택 |
| "재직증명서를 모은다" | 서류 수집·회수 |
| "철수하는 인력의 수행 평가서" | 종료 평가 |
| "남는 금액", "이익률" | 마진·수익률 |
| "사람을 찾기 시작한다" | 탐색·물색 |

- 잘못 맞힌 2건: "고객 인터뷰 후 채택되지 않은 두 명에게 결과를 알린다" → MEETING("고객…인터뷰"에 걸림), 복합 항목 → PROFITABILITY.
- C 55개의 1.000은 그 셋의 표현에 맞춘 결과라는 뜻이다.

**b. 임베딩+LR:** C 55개와 같은 양상이다(0.26~0.31). 양성 30개 중 18개를 NONE으로 답했다. C RESULTS.md가 말한 학습 문체 차이와 부류 불균형이 그대로 보인다.

**c. LLM**
1. **NONE 경계 함정에 약하다**(qwen 4/6, gemma 2/6 틀림). 둘 다 틀린 것:
   - "지난번 떨어진 지원자에게 새 공고가 열렸다고 연락한다" → REJECTION
   - "목요일 외근 나갈 준비를 한다" → VISIT

   qwen만 틀린 것: 공급업체 탐색 → SOURCING, "제안서를 보내고 수익성 표도 같이 만든다" → PROPOSAL. 경계표에 같은 유형 예시가 있는데도 틀렸다. 이 오류는 **쓸데없는 준비 알림**으로 이어진다(규칙 6).
2. **이웃 부류 혼동 (qwen):** "계약서 조항 비교" → DOC_COLLECTION, "이력서 묶어서 보낸다" → DOC_COLLECTION. "서류"라는 겉모습에 끌렸다.
3. **형식 실패 (gemma 5건, 모두 같은 원인):** `taskType`에 부류 코드 대신 서비스 번호 `"S-10"`을 냈다. 지시문 정의 줄이 "SOURCING_START — S-10 …" 모양이라 헷갈린 것으로 보인다. 규칙대로 NONE으로 셌다. 평가 결과를 보고 "S-10 → SOURCING_START"로 바꿔 읽으면 점수가 오르지만, 평가셋에 맞추는 사후 보정이라 수치에 넣지 않았다. 지시문에서 서비스 번호를 빼고 **새 문장으로 다시 재야** 한다.
4. **근거 한 줄은 믿기 어렵다:** qwen이 경계표 문구를 그대로 베끼거나(공급업체 문장에 "채용 포털에서 후보 검색"), 오타를 낸 경우("툕입", "마argin율")가 있었다. 근거를 화면에 증거처럼 보여 주기는 이르다.

**d. 시간:** CPU 기준 qwen은 건당 13~14초, gemma는 약 7초다. 할 일 5개짜리 회의록이면 qwen으로 약 1분이 더 걸린다. 규칙은 1ms 미만, 임베딩은 약 10ms다. GPU 환경 수치는 따로 재야 한다.

## 4. 판단 (추천 — 결정은 11/20)

1. **운영 분류기는 규칙을 유지한다.** LLM으로 통째로 바꾸는 것은 추천하지 않는다.
   - NONE 경계를 넘기는 오류가 알림을 늘린다.
   - CPU에서 건당 7~14초가 걸린다.
   - 근거 한 줄의 신뢰도가 낮다.
2. **규칙의 가장 큰 위험은 재현율이다.** 처음 보는 표현에서 0.316이다. 그런데 이 36개 표현을 규칙에 추가하면 같은 과적합이 반복된다.
   - **holdout을 규칙 수정에 쓰지 말자.** 쓰게 되면 새 평가셋이 다시 필요하다.
3. **LLM을 붙인다면 보조로.** "규칙이 부류를 냈으면 규칙, **규칙이 NONE일 때만 LLM**에 묻는" 방식이다.
   - 점수: C 55개는 1.000을 유지하고, 새 36개는 qwen 0.841, gemma 0.876.
   - 호출은 규칙이 NONE인 할 일에만 한다.
   - LLM이 고른 부류는 할 일 초안에 **"AI 추정 — 확인 필요"**로 표시하고, **사람이 확정하기 전에는 준비 알림을 만들지 않는다.** 할 일은 원래 사람이 하나씩 확정하므로(D-023 ⑤, 규칙 2) 흐름과 맞는다. 위 1번의 NONE 오분류도 이 확인 단계에서 걸러진다.
4. **모델은 gemma4:e4b가 더 정확하고 두 배 빠르다.** 다만 형식 실패(서비스 번호)를 고친 지시문으로 다시 재야 한다. 회의록 기본 모델(L-2, D-027 기본값 유지)과 묶어서 11/20에 정한다.

## 한계

- 새 36개는 **B 혼자 라벨을 붙였고 검수 전**이다. 다른 팀원의 교차 검수가 필요하다.
- 부류마다 3개라 부류별 F1은 한 문장에 크게 흔들린다. macro F1의 차이도 이 정도 표본 기준이다.
- B가 규칙 정규식을 읽은 뒤에 새 문장을 썼다. 자연스러운 표현을 쓰려 했지만, 의도치 않게 규칙 단어를 피한 문장이 있을 수 있다. 그래서 **규칙 0.316은 규칙에 불리한 쪽으로 치우쳤을 수 있다.**
- 같은 사람이 만든 합성 문장이다. 실제 영업 발화(가명) 성능은 아니다.
- 시간은 GPU 없는 이 PC 기준이다.
