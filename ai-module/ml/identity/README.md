## 실행

`ai-module/`에서 Python 환경을 활성화한 뒤 실행한다.
`pytest`·`jsonschema`는 기존 `requirements-test.txt`에 이미 포함돼 있어 의존성 파일 변경이 필요 없다.

```bash
# 새 가상환경이 필요한 경우에만
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-test.txt

python ml/identity/generate_dataset.py
python -m pytest tests ml/identity app/identity -q
```

기본 seed는 42다. 같은 seed면 같은 결과를 만든다. 전역 난수 상태는 변경하지 않는다.
다른 seed나 저장 폴더가 필요한 경우:

```bash
python ml/identity/generate_dataset.py --seed 7 --output-dir /tmp/identity-seed7
```

생성은 출력 폴더의 JSON 4개를 덮어쓴다. 기본 data/는 seed 42 결과로 유지한다.
검증을 먼저 마친 뒤 쓰므로 검증 실패 때는 기존 파일을 바꾸지 않는다.

## 인물 단위 분할

먼저 인물을 분할하고, 각 집합 안에서만 비교 쌍을 만든다.
다른 사람인 쌍도 양쪽 인물이 모두 같은 집합에 속해야 한다.
동명이인 10쌍은 학습에 8쌍·평가에 2쌍으로 배치한다.
동명이인 그룹 전체를 함께 나누므로 같은 이름·등록 별칭도 학습/평가 양쪽에 걸치지 않는다.
각 집합에 동명이인·같은 회사의 다른 인물·이전 소속을 가진 인물이 포함된다.

## 변형·반례

| 정답 | caseType | 뜻 | 학습 / 평가 |
| --- | --- | --- | --- |
| 같은 사람 | exact | 대표 이름, 연락처 일부 누락 | 200 / 50 |
| 같은 사람 | honorific | 직함·님 호칭이 붙은 이름 | 200 / 50 |
| 같은 사람 | english | 등록된 Synthetic Person 영문 별칭 | 200 / 50 |
| 같은 사람 | typo | 이름의 가상 표기 한 글자 오타 | 200 / 50 |
| 같은 사람 | company_change | 대장 이력에 있는 이전 회사·직함으로 언급 | 200 / 50 |
| 같음/애매함 | missing_company | 회사가 빠진 언급 | 200 / 50 |
| 다른 사람 | random | 서로 다른 인물을 무작위 비교 | 400 / 100 |
| 다름/애매함 | same_name | 이름은 같고 회사는 다른 두 사람 | 400 / 100 |
| 다른 사람 | same_company | 회사는 같고 이름은 다른 두 사람 | 400 / 100 |

같은 사람의 변형 언급에서는 이메일·전화를 비워 이름·소속 비교도 필요하게 만든다.
동명이인·같은 회사 반례도 연락처를 비워 쉬운 연락처 불일치만으로 구별하지 못하게 했다.
소속 이동은 두 사람이 된 것이 아니라 같은 인물의 현재 소속과 이력 소속이 다른 사례다.

## 계약과 실험 내부 형식

`persons.json`의 각 객체는 `contracts/person.schema.json`을 따른다.
쌍의 mentionA/B는 `identity_resolution.schema.json`의 mention 정의를 그대로 따른다.
이름·회사·직함·이메일·전화·채널·sourceRef만 넣고 계약 필드를 추가하지 않는다.
쌍 생성은 학습 정답을 만드는 작업이며 CONFIRMED 등 식별 결과를 생성하지 않는다.

비교 쌍·split 파일 자체는 ML-1 실험 내부 형식이다. 새 모듈 간 계약이 아니다.

| 비교 쌍 필드 | 용도 |
| --- | --- |
| pairId | 실험 내부의 비교 쌍 ID |
| label | 같은 사람 1 / 다른 사람 0 / 애매함 null. 생성 ID만으로 애매함을 단정하지 않음 |
| expected | 애매한 쌍의 kind=AMBIGUOUS·가능한 인물 집합·출처·이유 |
| caseType | 어떤 변형·반례로 만들었는지 |
| personIdA / personIdB | 양쪽 언급의 정답 인물 ID, 분할 검사용 |
| mentionA / mentionB | 모델이 비교할 관측 단서 |
| evidence | 각 언급에 대응하는 가짜 관측 원문 |

pairId·label·expected·caseType·정답 인물 ID·sourceRef·evidence를 모델 입력 특성으로 사용하지 않는다.
evidence는 관측 단서로 만든 가짜 텍스트이며 실제 메모·추출기를 검증한 자료가 아니다.
채워진 단서의 출처를 추적하고 교차 검수할 수 있도록 원문을 함께 남긴 것이다.

이번 데이터 수정에서 공용 CI나 tests/는 수정하지 않았다. 로컬도 같은 명령을 사용할 수 있다.

남은 검토:

- 총괄의 정답 교차 검수에서 나온 64건 수정은 반영했다. 추가 데이터의 교차 검수는 계속 필요하다.
- 유형별 비율·동명이인 개수와 관측 단서의 적절성. 고정 비율은 실제 사용 빈도가 아니다.
- 같은 관측 단서가 반복될 수 있어 3,000쌍이 모두 독립적인 관측을 뜻하지 않는다.
- 번호 기반 가상 이름과 한 종류의 오타는 실제 이름의 복잡성을 대표하지 않는다.
- 평가 인물은 모두 대장 안에 있다. 신규 인물 탐지 성능을 평가하는 데이터는 아니다.
- 교차 검수의 두 지적 사항은 DATA_REVIEW.md에 반영했다. 추가 유형의 정답 검수는 계속 필요하다.

팀 공유 후 decisions.md에 추가할 문장 제안:
“A의 ML-1 가짜 데이터는 인물을 먼저 학습/평가로 분리한 뒤 집합 내부에서 비교 쌍을 만들고,
같은 이름 그룹도 함께 배치하며 정답 인물 ID와 관측 단서를 구분한다.”
공용 결정 기록은 수정하지 않았다. 커밋·push·PR·다른 담당에게 메시지 발송은 하지 않았다.

## 내부 후보 검색 평가

```bash
python -m ml.identity.evaluate_candidates
# 다른 위치에 보고서 저장
python -m ml.identity.evaluate_candidates --output /tmp/candidate-evaluation.json
```

results/candidate_evaluation.json은 실험 보고서이며 외부 계약 응답이 아니다.
기본 실행은 보고서 파일을 덮어쓴다. 원본 데이터 4개는 변경하지 않는다.
학습 데이터에서 선택한 유사도 기준은 0.88이며 평가에는 고정해 사용했다.
600건의 정답 후보 포함률과 동점을 보수적으로 계산한 top-3 재현율은 91.7% → 100%,
오타 50건은 0 → 50건을 찾았다. 평균 후보는 1.132 → 1.262명이다.
다른 사람인 비교 쌍 300개 중 후보 포함은 100 → 101개로 늘었다.
자동 확정 정확도는 측정하지 않았으며 출력하는 확률 점수도 없다.
평가 대장은 60명이고 기존 인물만 있다. 번호형 가짜 이름과 반복 언급 때문에
이 수치를 실제 인물 식별 성능이나 전체 300명 대장 검색 성능으로 해석하면 안 된다.
평가셋을 확인했으므로 후속 기준 변경은 미사용 데이터로 다시 평가한다.
정확한 기준·동점 처리·검토 사항은 app/identity/RULES.md의 13절에 있다.
