# ML-1 자동 규정 재학습·전체 대장 비교

사람 검수 대기 없이, 자동 합성 정답·검사와 사전에 고정한 규정으로 재학습한 결과다.
규정은 `TRAINING_PROTOCOL.json`, 생성기는 `controlled_data.py`, 실행기는 `controlled_experiment.py`다.
결과·학습 전 동결 기록은 `results/controlled_v1/`에 있다. 기존 이진 쌍 비교 보고서는 별도 과거 실험으로 보존한다.

## 1. 결과를 보기 전에 고정한 규정

- 인물 그룹·동명이인·별칭·연락처가 다른 분할에 걸치지 않게 별도 seed로 생성한다.
- fit(가중치 학습), calibration(점수 보정), tune(모델 설정·후보 기준 선택), test(최종 비교)를 분리한다.
- 같은 관측은 중복 제거한다. 생성 출처만 아는 상황을 구분하고 같은 이름/소속으로 가능한 인물이 여럿이면 정답을 집합으로 남긴다.
- 이진 학습에는 KNOWN·NEW만 쓰고 AMBIGUOUS·CONFLICT·INSUFFICIENT는 0/1로 단정하지 않는다. 이 세 유형은 최종 동작 평가에 포함한다.
- 모델 입력은 기존 비교 단서 14개다. ID·원문 이름·연락처 문자열·정답·유형·출처를 특징에 넣지 않는다.
- fit에서 정답 외 어려운 음성 6개 + 무작위 음성 4개를 선택한다. 각 질문의 전체 가중치는 1로 맞춘다.
- LR의 스케일러는 fit에만 적합하고, 별도 calibration 인물의 전체 대장 쌍에 sigmoid 보정을 적합한다.
- LR C=0.1/1/10, GB 깊이 1/2/3(트리 100개, 학습률 0.1)을 비교한다. 후보 기준 9개는 tune에서만 고른다.
- 최종 시험을 본 뒤 하이퍼파라미터·기준·자료·합격 조건을 바꾸거나 다시 시험하지 않는다.
- 규정·코드 해시는 학습 전에 `frozen_protocol.json`, 자료/정답 해시는 특징 준비 전에 `frozen_data_manifest.json`으로 저장한다.

**사전 합격 조건:** 확정 정밀도 95% 이상, top-3 보장 재현율 90% 이상이면서 규칙보다 1%p 이상 악화되지 않음,
애매/충돌 후보 보존율도 규칙보다 1%p 이상 악화되지 않음, 신규 오후보 증가 1%p 이하, 정보 부족 안전 처리 유지,
로컬 계산 p95 100ms 이하. 이를 지키면서 **top-3 재현율 3%p 이상 증가 또는 질문당 불필요한 후보 0.15명 이상 감소** 중 하나를 달성해야 한다.
개선은 인물 그룹 단위 대응 bootstrap 95% 구간의 하한이 0보다 커야 한다. 늘어난 후보 수 자체를 탈락 조건으로 삼지는 않았으며 반드시 함께 보고한다.

규정은 결과에 맞춰 수정하지 않았다. 원래 계획한 자동 검증만 수행했으며 사람 교차 검수를 받은 정답이라고 표시하지 않는다.

## 2. 새 데이터와 학습 효율

기존 300명/3,000쌍·새 holdout/v1·기존 보고서를 읽어 재튜닝하거나 변경하지 않았다.
이번 실험은 별도 가짜 인물 300명, 중복 제거 후 질문 3,105개를 재현 생성했다.
이름은 `가상인물_` 뒤의 다양한 길이 토큰, 회사는 `가상회사_`와 `가상이전회사_`, 연락처는 `.example`과 `000-` 번호다.
신규 인물도 대장과 같은 가짜 이름 접두어를 사용해 신규 전용 표기를 모델이 이용하지 못하게 했다.

| 분할 | 인물 | 질문 |
| --- | ---: | ---: |
| fit | 120 | 1,240 |
| calibration | 40 | 415 |
| tune | 60 | 620 |
| test | 80 | 830 |

단일 정답 기존 인물·신규의 모든 대장 조합이면 fit은 111,480쌍이지만, 어려운 음성 샘플링으로 10,159쌍(양성 869)을 학습했다.
특징 벡터의 서로 다른 패턴은 301개로, 이전 실험의 30개보다 다양하다. 다만 여전히 반복 패턴이 있는 합성 자료다.
보정에는 별도 12,880쌍을 사용했다.

시험 830건: 단일 정답 기존 인물 589, 애매함 160, 연락처/이름 충돌 40, 신규 40, 정보 부족 1.
오타 삽입·삭제·교체·전치·여러 글자 변형, 별칭, 호칭, 현재/이전 소속, 소속 누락, 이메일만 있음, 공유 연락처를 포함한다.
자동 정답은 생성 시나리오와 관측상 가능한 인물 집합에 기반한다. 규칙이나 학습 모델의 출력으로 정답을 만들지 않았다.

## 3. 비교 조건

세 방식 모두 같은 질문과 같은 80명 전체 대장을 입력받고, CONFIRMED/CANDIDATES/NEW 및 후보 최대 3명을 평가한다.

- 규칙: 현재 운영의 0.88 후보 검색·순위와 같은 동작. 테스트에서 실제 engine과 결과/순서 일치를 대조했다.
- 학습 혼합: 연락처 정확 일치·정확 이름 후보는 삭제하지 않고, 학습 점수가 기준 이상인 후보를 추가한다.
  연락처 → 정확 이름 → 모델 점수 순서로 정렬한다.
- 세 방식 모두 **동일한 D-022 연락처/충돌 관문**으로만 CONFIRMED를 제안한다. 모델 점수만으로 확정하지 않는다.
- 동점은 ID 표시 순서의 우연한 이득을 빼고 최악 순위를 기준으로 top-3 재현율을 평가한다.
- 애매/충돌은 CANDIDATES로 가능한 정답 집합을 모두 표시했는지 검사한다.

학습 모델 점수는 별도 보정했지만 합성 조건에서의 진단일 뿐 실제 사람일 확률을 보증하지 않는다. 앱에 MODEL score를 내보내지 않았다.

## 4. 고정된 최종 시험 결과

| 지표 | 현재 규칙 | LR 혼합 | GB 혼합 |
| --- | ---: | ---: | ---: |
| 정답 top-3 보장 재현율 (589건) | 77.93% (459/589) | **100% (589/589)** | **98.98% (583/589)** |
| 애매/충돌의 가능한 후보 전부 보존 (200건) | 64.00% (128/200) | **100% (200/200)** | **98.50% (197/200)** |
| 신규를 NEW로 처리 (40건) | 100% | 100% | 100% |
| 기존 인물을 NEW로 놓침 | 130건 | **0건** | **6건** |
| 확정 제안 정밀도 | 100% (140/140) | 100% (140/140) | 100% (140/140) |
| 질문당 평균 표시 후보 | **1.167명** | 1.866명 | 1.742명 |
| 질문당 불필요한 후보 | **0.300명** | 0.669명 | 0.559명 |
| 로컬 계산 p95 (특징+모델, 전송/DB 제외) | 별도 서비스 부하 측정 없음 | 약 6.41ms | 약 6.38ms |

LR은 tune에서 C=10, 후보 추가 기준 0.02, GB는 깊이 3, 기준 0.05를 선택했다.
이 숫자는 **후보 추가용 보정 점수 경계**이며, 2%/5%를 넘으면 사람으로 확정한다는 뜻이 아니다.
학습 seed 7/42/97에서 예측/성능은 같았고, 두 방식 모두 사전 합격 조건을 통과했다.
결정적인 알고리즘/전체 샘플 학습이라 seed 반복은 새로운 독립 시험 3회가 아니다. 시험 인물·질문 수를 3배로 세지 않는다.

인물 그룹 20개를 함께 재표집한 대응 bootstrap 500회 결과:

- LR의 top-3 개선 +22.07%p, 95% 구간 **+20.03~+24.19%p**.
- GB의 top-3 개선 +21.05%p, 95% 구간 **+18.64~+23.40%p**.
- 불필요한 후보는 감소하지 않고 늘었다. LR은 +0.369명, GB는 +0.259명이다. 이 비용을 숨기지 않는다.

## 5. 결론과 해석

**이번 고정 합성 시나리오와 사전 규정에서는 두 학습 혼합 방식 모두 현재 규칙보다 정답을 덜 놓치는 개선이 확인됐다.**
후보를 더 넓게 보여주는 비용이 있으므로 모든 지표에서 더 낫다는 결론은 아니다.
놓침을 줄이는 선택은 LR, 조금 더 적은 후보를 보이는 절충은 GB다. tune에서도 LR의 재현율이 더 높았다.
확정 정밀도는 공통 안전 규칙의 결과여서 학습 모델이 확정을 더 잘했다고 해석하지 않는다.

이 결과는 단순 이진 쌍 점수와 달리 실제 요청과 같은 전체 대장 후보/판정 과제의 비교다.
다만 **현재 고정 규칙에 대한 비교**이며, 유사도 경계를 완화한 다른 규칙 변형보다도 우수하다는 비교는 하지 않았다.
생성기 편향·공통 가짜 이름 표식·자동 정답 가정이 있고 실제 고객 성능을 증명하지 않는다.
보정 대장은 40명, 시험 대장은 80명이므로 사전 확률 차이도 있다. 전체 쌍 Brier는 LR 0.00289, GB 0.00204이며 음성이 많은 진단값이다.

사람 검수를 진행 조건으로 다시 걸지 않았다. 이번 요청은 재학습·비교이므로 운영 코드 교체·새 기본값 적용은 수행하지 않았다.
후속 적용을 한다면 이 시험을 다시 조정용으로 쓰지 않고, 고정한 학습 설정과 후보 정책을 선택 가능한 모드로 연결해야 한다.
API 계약·기본 규칙·사용자 확인·신규 등록/병합 권한은 그대로다.

## 6. 재현과 검사

scikit-learn과 numpy가 있는 ai-module 환경에서 명시적으로 실행한다. 이번 실행은 scikit-learn 1.9.1, 모델 다운로드·유료 API·외부 호출 없이 로컬 CPU 계산만 사용했다.

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 python -m ml.identity.controlled_experiment \
  --output-dir /tmp/ml1-controlled-new-run
python -m pytest tests app ml -q -p no:cacheprovider
```

출력 폴더가 존재하면 덮어쓰지 않고 거절한다. 재실행은 재현 확인용이며 시험을 보고 설정을 바꾼 재튜닝은 별도 실험/새 시험 자료로 구분한다.
기본 테스트는 모델을 학습하거나 sklearn을 import하지 않는다. 데이터 분리·재현·형식·가짜 표기·중복 제거·정답 참조,
규칙 동작 일치·동점·충돌·애매함·학습 제외·질문 가중치·사전 gate·대응 bootstrap을 검사했다.

검사 결과: **508 passed, 4 warnings**. 경고는 기존 FastAPI 이벤트 사용 중단 안내다.
기존 사람 화면·백엔드 등 이번 요청 밖의 파일은 수정하지 않았다. 커밋·push·운영 DB 변경은 하지 않았다.
