# ML-1 과적합·환경 변화 추가 검사

현재 결론: **동일 생성기에서의 큰 학습–평가 격차는 발견하지 못했다. 다만 심한 이름 훼손·회사 누락에서는 그래디언트 부스팅의 애매한 후보 포괄률이 크게 떨어졌다.** 로지스틱 혼합 방식이 이번 추가 검사에서도 더 안정적이었다. 과적합이 없다는 보증이나 운영 모델 적용 결과는 아니다.

## 검사 방법

- 원 실험의 선택된 seed 42 모델만 재현: 로지스틱 C=10·기준 .02, 부스팅 깊이 3·기준 .05. 원 fit/calibration 자료만 학습에 사용하고 모델·특징·기준값을 바꾸지 않았다.
- 원 코드·데이터 해시, sklearn 버전과 기존 최종 평가 지표가 같은지 먼저 확인했다.
- 원 인물/오타 생성 함수를 재사용하지 않는 별도 생성기로 가짜 인물 80명, 질문 121개(20개 인물 그룹)를 만들었다. 한글 이름, 동명이인, 영문 별칭, 연락처 충돌, 신규·누락 정보를 포함한다.
- 일반 표기, 심한 표기 훼손, 대장 240명·800명 네 조건을 비교했다. 대장 확대는 같은 질문·정답을 유지하고 무관한 인물만 추가한다. 확대 조건은 독립된 질문 121개를 추가 확보한 것이 아니다.
- 일반 이름과 심한 훼손에서 알려진 단서가 다르므로 정답이 하나인 질문 수가 35→30, 애매한 질문 수가 65→70으로 달라진다. 같은 분모의 결과처럼 해석하지 않는다.
- 5%p 하락은 경고, 10%p는 큰 하락으로 정했다. 이는 이 실험의 내부 경보 기준이며 과적합의 보편적인 정의가 아니다.

## 결과

정답이 하나인 질문의 후보 3명 포함률(동점은 불리하게 채점):

| 모델 | 원 학습 | 원 튜닝 | 원 최종 평가 | 별도 일반 자료 | 대장 800명 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 로지스틱 혼합 | 100% | 100% | 100% | 35/35 | 35/35 |
| 부스팅 혼합 | 99.42% | 99.77% | 98.98% | 35/35 | 35/35 |

학습−원 최종 평가 격차는 각각 0%p, 약 0.44%p다. 이번 자료에서 학습만 잘하고 평가가 급락하는 형태는 보이지 않았다. 대장 240명 결과도 800명과 같다. 무관한 인물 확장 결과를 매우 비슷한 동명이인 수가 늘어나는 상황까지 일반화할 수는 없다.

애매하거나 충돌하는 질문에서 **가능한 정답 전부가 후보 3명에 포함되고 CANDIDATES로 나온 비율**:

| 조건 | 규칙 | 로지스틱 혼합 | 부스팅 혼합 |
| --- | ---: | ---: | ---: |
| 별도 일반 자료 | 65/65 (100%) | 65/65 (100%) | 65/65 (100%) |
| 심한 훼손·회사 누락 | 50/70 (71.43%) | 68/70 (97.14%) | 53/70 (75.71%) |
| 위 조건 중 이름 훼손 20건만 | 0/20 | 18/20 | 3/20 |

부스팅은 일반 자료 대비 애매한 후보 포괄률이 **24.29%p 하락**했다. 로지스틱도 훼손 유형 2건은 놓쳤으므로 전체 평균만 보고 완벽하다고 말할 수 없다. 심한 훼손은 이름 글자 삭제·순서 변경·회사 제거를 동반하므로 **환경 변화 또는 식별 정보 소실에 대한 취약성**이다. 이 결과만으로 학습 자료를 외운 과적합이라고 단정할 수 없다.

별도 자료에서 신규 20건 중 두 모델 모두 19건은 NEW, 1건은 불필요한 후보를 제시했다(규칙은 20/20). 연락처 기반 확정은 각 조건 20/20이지만 같은 보호 규칙을 사용하므로 학습 모델 덕분이라고 해석하지 않는다.

## 발견한 검사 사각지대

첫 실행의 진단은 단일 정답 포함률만 경보에 사용해, 애매한 후보 누락을 자동 경보로 잡지 못했다. 이를 발견한 뒤 **애매한 후보 포괄률 경보를 추가**하고 같은 모델·자료로 다시 보고서를 만들었다. `OVERFIT_AUDIT_PROTOCOL.json`에 사후 보완 사실을 기록했다. 최초 결과도 `initial_diagnostic/`에 보존한다. 이 재실행은 새로운 미사용 평가가 아니며 모델·임계값은 재선택하지 않았다.

## 대처

1. 현 비교에서는 로지스틱 혼합을 우선 검토한다. 부스팅은 심한 훼손 조건에서 회귀가 확인됐으므로 그대로 대체하는 근거로 사용하지 않는다.
2. 모델 점수로 자동 확정하지 않는 기존 연락처·충돌 보호 규칙을 유지한다. 단서가 부족하면 회사·이메일 등 추가 정보를 요청하거나 직접 검색하게 한다. 규칙으로 무조건 되돌려도 위 훼손 자료에서는 더 나빠진다.
3. 전체 점수 외에 유형별 후보 포함률, 애매한 후보 포괄률, 신규 인물의 불필요한 후보 비율을 별도로 감시한다. 드문 유형의 실패가 평균에 가려지지 않게 한다.
4. 다음 개선에서는 로지스틱 규제 강화(C 감소), 부스팅 깊이·복잡도 축소, 다양한 훼손 자료를 검토할 수 있다. **현재 시험 결과를 보고 바꾼 뒤 같은 시험으로 개선을 입증하지 않는다.** 새 생성 규칙·새 인물 그룹의 미사용 자료를 먼저 고정하고 평가한다.
5. 새 자료에서도 유형별 큰 하락이 없고 후보 누락·신규 오탐의 비용이 허용 범위인지 확인한 뒤 적용한다. 이 검사는 운영 코드·API·스키마를 바꾸지 않았다.

독립 자료 역시 자동 생성 정답이며 20그룹, 신규 20건 등 표본이 작다. 실제 업무 전반의 오류율·과적합 부재를 입증하지는 않는다. 평가를 위해 기존 `holdout/v1`은 읽지 않았다.

## 재현

```bash
cd ai-module
.venv/bin/python -m ml.identity.overfit_audit --output-dir /tmp/a-overfit-new-run
.venv/bin/python -m pytest ml/identity/test_overfit_audit.py -q
```

출력 폴더가 이미 있으면 덮어쓰지 않는다. 학습 실행에만 원 실험과 같은 sklearn이 필요하다. 기본 테스트는 모델 학습·네트워크를 사용하지 않는다.

결과: `results/overfit_audit_v1/report.json`, 원 실험: `results/controlled_v1/report.json`.
