# ML-1 학습 비교 — 규칙 / 로지스틱 회귀 / 그래디언트 부스팅

2026-11-12. `learned_comparison.py`로 **실제 두 분류기를 학습**했다. 모델·기준 선택은 train 내부에서만 했고 기존 eval 600쌍은 선택 후 비교했다.
결과는 `results/ml1_pair_comparison.json`이다. 운영 API/score/판정/후보 검색은 변경하지 않는다.

## 무엇을 비교했나

대장의 후보 A와 관측 언급 B가 같은 사람인지 판단하는 **이진 쌍 분류**다.
정답 ID는 대장에서 비교할 후보를 조회하고 분할·채점할 때만 쓴다. 모델 입력에는 ID·숫자형 이름 원문·정답·caseType·sourceRef·evidence를 넣지 않는다.

특징 14개: 이름 정확 일치/문자 유사도/정보 부족/불일치, 이메일·전화·현재 또는 이전 소속의 일치/부족/불일치, 연락처 충돌 경고.
두 모델과 규칙 모두 같은 후보·언급·분할별 대장 비교를 사용한다. 규칙 기준은 기존 0.88 후보 검색이 해당 A를 포함하면 양성으로 보는 것이다.
**이 기준은 후보를 넓게 남기도록 설계돼 있어, 사람 확인 전 CONFIRMED 판정과 다르다.**

- LR: StandardScaler + LogisticRegression(C=1, solver=lbfgs, max_iter=2000, seed=42).
- GB: GradientBoostingClassifier(loss=log_loss, n_estimators=100, learning_rate=0.1, max_depth=2, subsample=1, seed=42).
- 하이퍼파라미터는 사전에 고정했다. 각 모델의 0.50/0.60/0.70/0.80/0.90/0.95 기준은 tune에서만 선택했다.
- 선택 기준은 tune 정밀도 95% 이상 달성 여부 → F1 → 정밀도 → 높은 기준이다. 모델 선택은 tune의 95% 충족 여부 → F1이며 동점이면 단순한 LR을 고른다.
- StandardScaler도 fit에서만 학습했다. eval로 재학습/선택하지 않았다. 모델 파일은 저장하거나 앱에 로드하지 않는다.

## 데이터 분할

기존 train 240명을 동명이인·등록 별칭의 연결 그룹 단위로 다시 분리했다.

| 구분 | 인물 | 쌍 | 같은 / 다른 |
| --- | ---: | ---: | ---: |
| fit (가중치 학습) | 191 | 1,690 | 937 / 753 |
| tune (기준·모델 선택) | 49 | 375 | 252 / 123 |
| 기존 eval (선택 후 평가) | 60 | 600 | 300 / 300 |

train의 AMBIGUOUS 64쌍은 이진 학습·평가에서 제외했다. fit/tune 인물을 가로지르는 271쌍도 제외했다.
fit/tune/eval 인물은 겹치지 않는다. 기존 JSON은 재생성·변경하지 않았고 해시를 결과에 남겼다.
새 holdout/v1은 읽거나 평가하지 않았다. 기존 eval은 과거에도 확인한 자료여서 새 독립 검증 자료가 아니다.

## 실제 실행 결과

| 방법 | 기준 | TP / FP / TN / FN | 정밀도 | 재현율 | F1 |
| --- | ---: | --- | ---: | ---: | ---: |
| 규칙의 후보 포함을 이진 예측으로 사용 | 기존 0.88 | 300 / 101 / 199 / 0 | 74.81% | 100% | 85.59% |
| 로지스틱 회귀 | 0.90 | 300 / 1 / 299 / 0 | 99.67% | 100% | 99.83% |
| 그래디언트 부스팅 | 0.95 | 300 / 1 / 299 / 0 | 99.67% | 100% | 99.83% |

모델 선택은 tune에서 동점이라 LR이다. 두 모델 모두 `pair_eval_0441`(same_company)을 거짓 양성으로 분류했다.
가중치/중요도·경계값별 tune 결과·유형별 eval·오분류·Brier/ROC AUC는 JSON에 기록했다.

## 해석·제약

- **이 표는 기존 후보 top-3 재현율 100%와 다른 과제다.** 모델이 실제 앱의 확정 정확도 99.67%를 달성했다는 뜻이 아니다.
- fit 1,690쌍이 14개 특징으로 바뀌면 서로 다른 특징 벡터는 **30개뿐**이다. 번호형 가짜 이름·반복 단서로 단순한 합성 분포에 과적합됐을 가능성이 크다.
- 후보 포함 규칙은 원래 오연결을 확정하지 않고 사람에게 넓게 제시한다. 거짓 후보 감소만으로 운영보다 우월하다고 단정하지 않는다.
- predict_proba는 보정되지 않은 모델 점수다. 0.9가 실제로 90% 확률이라는 검증은 없다. Brier는 진단값이며 확률 보정을 완료했다는 뜻이 아니다.
- 신규 인물 탐지·전체 대장 top-3 순위·AMBIGUOUS의 사용자 확인·공유 연락처 등 별도 상황에서의 모델 성능은 이번 학습 비교로 입증하지 않았다.
- 기존 API의 D-022 연락처 조건을 완화하지 않는다. MODEL score를 계약 응답에 넣지도 않는다.

**결론: 학습 모델 비교 단계는 수행했으나 운영 규칙은 유지한다.** 검수된 새 자료에서 전체 대장 검색·확정 오판·모호함·신규/누락/충돌과 확률 보정을 함께 평가한 뒤 팀이 채택 여부를 결정해야 한다.

## 재현

ai-module에서 scikit-learn이 설치된 환경으로 실행한다. 이번 환경은 scikit-learn 1.9.1이다. 로컬 계산만 하고 모델 다운로드·유료 API 호출은 없다.

```bash
python -m ml.identity.learned_comparison --output /tmp/ml1-pair-new.json
python -m pytest ml/identity/test_learned_comparison.py -q
```

결과 파일이 이미 있으면 덮어쓰지 않고 거절한다. 같은 seed와 라이브러리 버전으로 재현한다.
기본 테스트는 sklearn을 import하거나 학습하지 않는다. 입력 누수·동명이인/별칭 그룹·애매함 제외·분할 간 쌍 제거·채점·기준 선택을 검사한다.
선택 실험이므로 공용 requirements-test.txt를 수정하지 않았다.
