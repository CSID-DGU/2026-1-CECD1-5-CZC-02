# A — 로컬 BGE-M3 비교 실험

실험 코드는 app/identity/embedding.py와 ml/identity/compare_embeddings.py다.
기존 규칙·후보 검색의 기본 동작은 변경하지 않았다. API나 확률 점수를 만들지 않는다.
공용 환경 파일·의존성 파일·다른 담당 코드는 수정하지 않았다.

## 실행

ai-module/에서 선택 임베딩 라이브러리가 설치된 Python 환경을 사용한다.
`sentence-transformers`는 기존 필수 테스트 의존성이 아니며, 비교 실험을 실행할 때만 필요하다.
모델 폴더는 미리 다운로드돼 있어야 한다. 이 코드는 모델을 다운로드하지 않는다.

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 python -m ml.identity.compare_embeddings \
  --model "$HOME/Models/bge-m3"
```

기본 보고서는 results/embedding_comparison.json이며 재실행하면 덮어쓴다.
다른 위치가 필요하면 `--output /tmp/embedding-comparison.json`을 지정한다.
CPU·batch 8·최대 토큰 64로 dense 임베딩만 사용한다. sparse/ColBERT는 비교하지 않는다.
전체 문서가 아닌 짧은 이름·소속 문자열을 비교하는 실험이다.
로딩/실행은 명시적인 CLI 실행 시에만 일어나며 앱 시작·기본 테스트에서 모델을 로드하지 않는다.
로컬 모델·선택 라이브러리 부재 또는 로컬 파일 로딩 오류는 rules_only 상태와 이유를 기록하고
규칙 평가를 수행한다. 추론 중 예기치 않은 오류는 숨기지 않고 실행 실패로 알린다.

## 무엇을 비교하나

임베딩은 문자열을 숫자 벡터로 바꾼 것이다. 벡터 방향의 유사함을 코사인 유사도로 비교한다.
이 유사도는 -1~1이며 같은 사람일 확률이 아니다.

입력 텍스트는 정규화한 이름과 소속뿐이다. 대표 이름·등록 별칭과 현재/이전 소속의 조합을
각각 만들고 가장 높은 코사인 유사도를 사용한다. 이메일·전화는 기존 규칙에서만 비교한다.
정답 ID·caseType·label·근거·원본 ID·채널은 벡터에 넣지 않는다.

- 기존 규칙의 유사도 기준은 기존 train에서만 선택한다.
- 마지막 문자열 순위에 임베딩을 반영하는 비율 0 / 0.25 / 1을 비교한다.
- 임베딩 후보 추가 기준은 비활성 / 0.80 / 0.90 / 0.95를 비교한다.
- 추가 후보도 이름 비교가 가능하고 현재/이전 회사가 일치해야 한다.
- 연락처 일치 개수 → 정확 이름 → 소속 우선순위는 유지한다.
- 공유 연락처·이메일/전화 대상 충돌 경고도 보존하며 자동 확정하지 않는다.
- 전체 후보를 보존한다. 동점은 ID 표시 순서로 성공을 부풀리지 않는다.

선택은 train의 동점 최악 순위 top-3 → top-1 → 거짓 후보 적음 → 평균 후보 수 적음 순이다.
같은 성능이면 후보 추가 비활성·임베딩 반영 비율 0을 선호한다.
기존 eval은 선택 후 비교만 하며 설정을 다시 고르는 데 쓰지 않는다.
최선의 임베딩 사용 설정도 train에서 별도로 골라 동일 eval에 보고한다.

새 holdout/v1의 검색·성능 평가는 하지 않는다. 자료 자체의 계약 검사는 기본 테스트에 포함된다.
기존 eval은 이미 확인한 데이터이고 가짜 번호형 이름·반복 언급·기존 인물만 있어
실제 성능이나 신규 인물 처리 성능을 증명하지 않는다.
설정을 바꾸고 난 뒤 새 holdout 결과를 보고 재조정하면 새 미사용 자료가 다시 필요하다.

## 검사

```bash
python -m pytest tests ml/identity app/identity -q
```

가짜 벡터와 기존 가짜 데이터만 사용한다. 실제 모델·torch·sentence-transformers를 테스트에서
로드하지 않는다. 텍스트 입력 제한·코사인 계산·후보 조건·순위 우선순위·경고·학습 선택·
로컬 모델 부재 시 규칙 동작을 검사한다.

## 2026-10-15 실행 결과

로컬 BGE-M3를 실제 로드해 실행했다. 결과는 results/embedding_comparison.json에 있다.
모델 파일 해시와 라이브러리 버전도 기록했다. 모델 파일 자체는 레포에 넣지 않는다.

학습에서 선택된 설정은 후보 추가 비활성, 임베딩 반영 비율 0.25다.
학습의 top-1 보장 재현율은 규칙 97.083% → 혼합 97.250%였다.
기존 평가 600건의 top-1/top-3 보장 재현율은 두 방식 모두 100%로 같았다.
평균 후보 수도 1.262명, 쌍별 거짓 후보 포함은 101/300으로 동일했다.
따라서 **현재 기본 규칙 유지**가 결론이다(keep_rules_no_eval_gain).
임베딩은 개선이 입증돼 기본 적용된 상태가 아니라 선택 실험 코드로만 남겼다.

학습 이득만으로 채택하지 않는다. 기존 eval은 이미 여러 번 확인했고 쉬운 합성 분포라
차이가 드러나지 않을 수 있다. 새 holdout은 이번 비교에서 읽거나 평가하지 않았다.
새 자료로 비교하려면 모호한 정답 집합·충돌·신규·정보 부족을 따로 다루는 평가기가 먼저 필요하다.

이 실행은 CPU에서 모델 로딩·벡터 생성·탐색·평가에 약 122초가 걸렸다.
이는 단일 실험 전체 소요 시간이며 요청당 지연 시간이나 속도 벤치마크가 아니다.
