# 새로운 합성 검증 자료 평가 v1

새 가짜 인물 **240명**, 40개 그룹, **560개 관측 질문**을 생성했다. 기존 모델을 수정하지 않고 별도의 시나리오 구현으로 후보 검색을 시험했다. 자유로운 메모에서 인물을 추출하는 시험이 아니라, 추출된 `mention`과 대장을 비교하는 A 내부 평가다.

## 결과

| 지표 | 기존 규칙 | 규칙+로지스틱 | 규칙+부스팅 |
| --- | ---: | ---: | ---: |
| 단일 정답 후보 3명 포함(320건) | 213/320 (66.56%) | **320/320 (100%)** | 280/320 (87.5%) |
| 애매함·충돌의 가능한 정답 모두 포함(최대 3명인 120건) | 120/120 | 120/120 | 120/120 |
| 신규 인물 후보 없음(40건) | 40/40 | 40/40 | 40/40 |
| 식별 단서 부족 시 후보 없음(40건) | 40/40 | 40/40 | 40/40 |
| 연락처 기반 확정 중 정답 | 80/80 | 80/80 | 80/80 |
| 질문당 불필요한 후보(전체 560건) | 0.214명 | 0.445명 | 0.214명 |

로지스틱 혼합은 단일 정답 포함률을 **33.44%p** 높였고 규칙이 놓친 107건을 찾았다. 불필요한 후보는 질문당 약 **0.23명 증가**했다. 인물 그룹별 대응 재표집 95% 구간은 포함률 증가 31.56~35.00%p다. 이 구간은 이 생성 자료 안의 변동만 나타내며 실제 업무 성능의 보장 범위는 아니다.

복합 오타·소속 있음은 규칙 13/40 → 로지스틱 40/40, 복합 오타·소속 없음은 0/40 → 40/40이다. 등록 영문 별칭의 구분자 변형·소속 없음은 규칙 0/40, 로지스틱 40/40, 부스팅 0/40이다. 부스팅은 원 평가 98.98%에서 새 단일 정답 포함률 87.5%로 약 11.48%p 하락했으며, 원 규정의 90% 기준에도 미달한다.

확정은 모든 방식이 동일한 기존 연락처 보호 규칙을 사용한다. 따라서 80/80을 모델 자체의 확정 능력 향상으로 해석하면 안 된다. 모델 점수만으로 확정하는 코드를 추가하지 않았다.

## 후보 최대 3명이라는 한계

나머지 40건은 이름·소속 없는 연락처가 아니라 **이름은 같고 회사·연락처가 없는 동명이인 4명**이다. 가능한 정답 4명을 후보 3명 안에 모두 넣는 것은 불가능하다. 세 방식 모두 CANDIDATES로 내지만 가능한 정답 전부 포함률은 0/40이다.

이 40건을 포함하면 전체 애매한 질문 160건의 포괄률은 세 방식 모두 **120/160=75%**다. 결과에서 이 한계를 지우지 않았고, 후보 수 안에서 해결 가능한 120건도 별도로 표시했다. 사용자 직접 검색 또는 추가 단서가 필요하다. 계약의 최대 3명은 변경하지 않았다.

## 생성·평가를 고정한 방법

- `fresh_validation.py`의 별도 생성 구현, seed 816293. 기존 `controlled_data`/`stress_data`의 인물·오타 생성 함수를 재사용하지 않았다. 원 모델 재현을 위해 원 `make_corpus`만 따로 사용했다.
- 가짜 표시가 있는 새 한글 인물명·회사명, `.example` 이메일, 000 전화번호만 사용했다. person/mention 스키마 검사, 원 학습 분할과 인물 ID·대표 이름 분리, 동일 관측 중복 방지를 검사했다.
- 새 자료와 자동 정답을 `dataset.json`에 먼저 저장하고 그 해시와 모델·기준을 `frozen_protocol.json`에 기록한 뒤 점수를 계산했다.
- 로지스틱 C=10/후보 기준 .02, 부스팅 깊이 3/후보 기준 .05, seed 42를 원 결과 그대로 사용했다. 새 자료로 학습·확률 보정·기준값 선택을 하지 않았다.
- 원 fit/calibration 자료만으로 모델을 재현하고, 원 최종 평가 지표가 정확히 재현되는지 확인한 뒤 새 자료에 적용했다.
- 원 최종 평가·기존 감사 결과·`holdout/v1`을 덮어쓰지 않았다. `holdout/v1`은 이번 모델 평가에서 읽지 않았다. 운영 API·DB·화면은 변경하지 않았다.
- 모든 유형과 4명 초과 정답을 평가 전에 정의했으며 결과가 나쁘다고 질문을 제외하거나 모델을 다시 고르지 않았다.

## 해석과 다음 선택

이번 새 시험도 로지스틱 혼합의 **후보 누락 감소**를 지지한다. 부스팅보다 우선 검토할 근거가 추가됐다. 다만 새 시험에서 100%가 나왔다는 것이 과적합 부재나 모든 실제 이름에서 100%라는 뜻은 아니다.

한계: 40개 합성 그룹·유형별 40건의 자동 정답이다. 가짜 이름의 공통 접두사, 비슷한 영문 별칭 템플릿, 제한된 훼손 방식의 영향이 남는다. 신규 이름은 기존 이름과 확실히 다른 경우만 만들었으므로 **이름이 비슷한 신규 사람과 기존 사람의 오타를 구분하는 능력은 검증하지 않았다.** 정답이 단일한 오타 사례도 생성 출처에 따른 가정이며, 사람이 현실에서 단정할 수 있다는 보장은 아니다. 확률 수치의 실제 업무 보정도 검증한 것이 아니다. 질문 간 같은 인물 그룹의 상관관계를 고려해 그룹 단위로 재표집했다.

운영 적용의 의미는 완벽한 확정기가 아니라 **후보를 더 넓게 찾는 보조 기능**이다. 기존 연락처·충돌 보호와 사람 선택·직접 검색을 유지해야 한다. 이번 자료도 이제 결과를 확인했으므로 향후 미사용 평가 자료라고 다시 부르면 안 된다.

## 파일과 재현

PR #48 후속 보관 정책·파일 크기·원본 추적 방법은 [ARTIFACTS.md](ARTIFACTS.md)에 있다.

- 생성·평가: `fresh_validation.py`
- 결과: `results/fresh_validation_v1/report.json`
- 새 자료·정답: 고정 seed와 해시로 `reproduce_fresh_data.py`에서 재생성한다 (큰 dataset.json은 Git에서 제거).
- 질문별 모델 후보: 전체 목록은 원 실험 재현 명령으로 생성한다. 기본 검사에는 기존 결과에서 추출한 앞 56건의 `results/fresh_validation_v1/runtime_predictions.json`을 사용한다.
- 평가 전 고정 기록: `results/fresh_validation_v1/frozen_protocol.json`

```bash
cd ai-module
# 모델 없이 자료만 재생성; 원 평가 해시 일치를 먼저 확인
.venv/bin/python -m ml.identity.reproduce_fresh_data --output /tmp/a-fresh-dataset.json
# 전체 모델 예측 재현 (기존 실험과 같은 sklearn 필요)
.venv/bin/python -m ml.identity.fresh_validation --output-dir /tmp/a-fresh-new-output
.venv/bin/python -m pytest ml/identity/test_fresh_validation.py -q
```

기존 폴더를 지정하면 덮어쓰지 않고 중단한다. 모델 실행에는 원 실험과 같은 sklearn이 필요하다. 기본 테스트는 모델 학습·네트워크 호출 없이 동작한다.
