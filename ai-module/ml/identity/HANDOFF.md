### 이번 연결 수정

AI 기본 출력은 RULE과 MODEL을 섞어 반환한다. A 백엔드의 이전 RULE 전용 검사가 MODEL을 거절하던 문제를 수정했다.
RULE 후보 score는 null, MODEL 후보 score는 유한한 0~1 수와 모델 버전을 요구한다.
MODEL이 CONFIRMED를 반환하거나 HUMAN을 가장하면 거절한다. 사용자 선택 후에는 HUMAN·score=null로 저장하고
수정 기록의 원래 제안자 MODEL과 모델 버전을 보존한다. contracts 변경은 없다.

## PR #48 리뷰 후속 5개

1. 참석자/perPerson JSON이 깨진 노트만 이력에서 제외하고 noteId만 경고 로그에 남긴다. 두 배열 전체를 검사하고 제외 뒤 페이지를 계산한다. DB/서비스 장애는 숨기지 않는다.
2. 재생성 가능한 dataset·전체 predictions를 제거하고, 기존 logistic 56건 스냅샷과 필수 원 학습 보고서를 보존했다. 대상 자료는 1,306,074 → 397,471바이트(69.6% 감소). [보관·재현 규칙](ARTIFACTS.md) 참고.
3. 공용 DashboardLayout의 사람 메뉴 아이콘만 ContactRound로 구분했다. 사용자 요청 범위의 공용 파일 수정이다.
4. 개발용 people.html·people-entry.jsx를 삭제하고 기존 `/people` 보호 경로를 유지한다.
5. 혼합 API의 후보 수 안내는 첫 후보에만 넣고 화면에서는 목록 위에 한 번 보여 준다. 이전 RULE 응답의 반복 안내도 중복 제거하며 후보별 근거는 남긴다.

원본 데이터는 재생성 명령으로 JSON 바이트까지 일치함을 확인했고, 원 controlled 보고서·모델 계수는 변경하지 않았다.
후보 검색/순위/확정 기준과 contracts·B 코드도 변경하지 않았다. 이번 후속의 커밋·push·리뷰 상태는 `s2/a-review-followups` 브랜치의 PR에서 확인한다.

## 다른 담당자와 이어야 하는 일

| 남은 일 | 담당·연결 경계 | 완료 기준 |
| --- | --- | --- |
| 사람 선택을 회의록에 반영 | B: participants/perPerson, 동명이인·이메일만 있는 참석자 대응, 확정 전 검사 | A 선택 저장 후 회의록을 재조회하면 정확한 personId가 유지됨 |
| 사람별 할 일 | C: counterpart 참조·보관 정책 | 동일 personId의 실제 할 일만 표시 |
| 다음 미팅 준비 | D: 브리핑 진입점·권한·대상 미팅 | 실제 연결 가능한 미팅만 열고 추측한 일정을 만들지 않음 |
| 앱 전체 인수 검사 | B 반영 후 A/B 공동 | 가짜 메모 → 인물 선택 → 회의록 확정 → 사람별 이력까지 실제 브라우저로 확인 |

A 저장 성공을 B/C 데이터 반영 성공으로 표시하지 않는다. 사람 화면은 확정 회의록에 이미 저장된 personId만 조회한다.
고객/계약 인력 필터, 열린 약속 상태, 할 일 수, 다음 준비 버튼은 근거·연결이 없는 동안 만들거나 추측하지 않는다.
사람 화면에서 독립 수정/삭제/병합을 추가하는 것은 이번 작업 범위가 아니다.

## 검증의 한계

- 모든 모델 평가는 합성 자료다. 좋은 점수도 실제 업무 성능·실제 동일 인물 확률을 증명하지 않는다.
- 후보가 3명을 넘으면 직접 검색과 추가 단서가 필요하다. 모델 점수만으로 자동 확정하지 않는다.
- 실제 브라우저 클릭·기존 앱 DB 이행·B/C/D 연결은 자동 검사 통과와 별개다.
- 사람별 이력은 현재 본인 회의록을 읽어 선별하는 초기 방식이다. 대량 데이터 성능은 측정되지 않았다.
- 현재 변경은 A 폴더 안에 한정한다. 팀 메시지·PR 등록·push는 별도 요청 없이 수행하지 않는다.
