# A — 새 가짜 검증 자료 v1

생성 seed: 20261015. 기존 모델·검색의 기준 조정에 사용하지 않은 별도 자료다.
이번 작업에서는 생성·형식·정답 참조만 검사했다. 모델 검색·임베딩·성능 평가는 실행하지 않았다.
`manifest.json`의 modelEvaluationPerformed=false는 **생성 시점 상태**다.
이후 평가할 때는 사용한 코드·모델·기준·실행 시점을 별도 결과 보고서에 기록한다.

## 구성

| 파일 | 내용 |
| --- | --- |
| v1/persons.json | 검색 대장 120명. Person 계약 준수 |
| v1/newcomers.json | 검색 대장 밖의 가짜 인물 20명. 정답 검수용 |
| v1/queries.json | mention 계약을 따르는 언급 300건과 실험 내부 정답·원문 |
| v1/manifest.json | seed·유형별 개수·파일 해시·기존 인물 파일 해시 |

기존 300명과 ID·정규화한 이름/별칭·연락처가 겹치지 않도록 검사한다.
이번 자료를 다시 학습/평가로 나누지 않는다. 전체를 미사용 검증 자료로 보관한다.
가상검증인물/가상검증회사, .example 이메일, 000-으로 시작하는 가짜 번호만 사용한다.
기존 data/ 및 모델·순위 기준 코드는 변경하지 않았다.

15유형을 각 20건씩 만들었다: 정확 표기·호칭·영문 별칭, 오타 4종(교체/삭제/삽입/인접 순서 바꿈),
소속 이동·소속 누락, 같은 회사 동명이인, 공유 이메일·공유 전화, 연락처 충돌, 신규 인물, 정보 부족.
오타는 고정된 가상 접두어 대신 가변 토큰의 여러 위치를 바꾼다.

## 실험 내부 정답

queryId·caseType·expected·evidence는 실험 내부 정보이며 계약 필드가 아니다.
모델 입력은 mention과 persons.json만 사용한다. newcomers.json을 검색 대장에 넣으면 안 된다.
expected·유형·정답 ID·근거·sourceRef를 식별 특성으로 사용하지 않는다.

| expected.kind | 건수 | 의미 |
| --- | ---: | --- |
| KNOWN | 180 | 대장의 기존 인물. targetPersonIds에 정답 1명 |
| AMBIGUOUS | 60 | 주어진 단서로 가능한 정답 2명. 한 명을 억지로 확정하지 않음 |
| CONFLICT | 20 | 이메일과 전화가 서로 다른 인물에 속함. 유일한 정답 없음 |
| NEW | 20 | 실제 출처 인물이 검색 대장 밖에 있음 |
| INSUFFICIENT | 20 | 비교 단서 없음. 신규라고 단정하지 않음 |

relatedPersonIds는 원문 단서의 생성 출처·검수 참조다. CONFLICT에서는 서로 다른 두 인물,
NEW에서는 newcomers.json의 인물, INSUFFICIENT에서는 빈 배열이다.
이 kind는 **실험 정답 구분**이며 외부 IdentityResolution의 decision을 바꾼 것이 아니다.
충돌·정보 부족을 NEW나 정답 한 명으로 변환해 기존 평가기에 넣지 않는다.
모호한 입력은 정답 집합 보존, 충돌은 경고, 신규는 불필요한 후보, 정보 부족은 판단 유보를
각각 검사하는 평가기가 필요하다. 기존 evaluate_candidates는 이 형식을 지원하지 않는다.

## 생성·검사

ai-module/에서 실행한다.

```bash
python -m ml.identity.generate_holdout
python -m pytest tests ml/identity app/identity -q
```

이미 v1 폴더가 있으면 재생성을 거절한다. 기존 검증 자료를 자동 덮어쓰지 않는다.
추가 버전이 필요할 때만 다른 seed와 새 폴더를 명시한다.

```bash
python -m ml.identity.generate_holdout --seed 7 --output-dir /tmp/identity-holdout-seed7
```

검증을 마친 뒤 새 폴더를 만든다. 오류로 쓰기가 중단되면 폴더가 일부 생성될 수 있다.
해시로 파일을 확인하고, 재실행 시 기존 폴더를 거절하는 원인을 먼저 확인한다.
검사에서는 인물/mention 계약, 분리, 유형·참조·원문 일관성, 오타 변형,
정답 오염 거절, 파일 해시와 기존 데이터 보존을 확인한다.
2026-10-15 전체 **238 passed, 5 warnings** (기존 라이브러리 경고).

## 사용 전 검토·한계

- 만든 사람이 아닌 팀원의 정답 교차 검수는 아직 필요하다.
- 명백한 가짜 이름의 긴 공통 접두어와 임의 영문 토큰은 자연어 인명 분포를 대표하지 않는다.
- 신규 인물 이름에는 별도 가짜 접두어가 있어 신규 사례가 쉽게 구분될 수 있다.
- 회사·연락처 공유 비율과 유형별 균등 비율은 실제 발생 빈도가 아니다.
- 같은 출처 인물을 여러 유형에서 재사용하므로 300건이 독립 인물 300명을 뜻하지 않는다.
- 이름을 가리거나 연락처를 섞은 것은 합성 스트레스 검사이며 실제 추출기를 검증하지 않는다.
- 모델·임계값은 기존 학습 데이터에서 정하고 고정한 뒤 이 자료를 평가한다.
  결과를 보고 기준을 바꿨다면 이 자료를 계속 미사용 검증이라고 부르지 않는다.
